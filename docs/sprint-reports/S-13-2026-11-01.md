# Отчёт S-13 — RAG: pgvector 768 (ingest + retrieval)

**Дата:** 2026-11-01 · **Этап:** E-05 RAG и сквозной ассистент · **Статус:** ✅

## 1. Что сделано

- Миграция `0009_rag`: `rag_documents` (tsv — GENERATED to_tsvector
  russian + GIN-индекс; embed Vector(768)) + `rag_chunks` (embed + **HNSW
  vector_cosine_ops**, uq-связь с документом).
- `backend/rag/`:
  - `embeddings.py` — EmbeddingProvider: OpenAI-compat `/embeddings`
    (модель `LLM_EMBED_MODEL`, открытый вопрос §18.2) + **hash-фолбэк**
    (детерминированный bag-of-words 768, L2-нормализация) — режим
    `embedMode` фиксируется в ответе/мета;
  - `ingest.py` — чанкинг (800 симв./перекрытие 100, разрыв по абзацам),
    замена документа по title (чанки каскадом);
  - `retrieval.py` — top-k cosine (pgvector `<=>`), фильтр доменов;
  - `router.py` — admin: `POST /admin/rag/ingest`, `GET /admin/rag/search`.
- Seeds: 7 обучающих документов (python: циклы/функции/условия/отладка;
  chess: вилки/висячие/расчёт) — seed-корпус для eval и RAG-контекста (S-14).
- `scripts/rag_eval.py` — 6 запросов → топ-1 по ожидаемому документу
  (R-04, ручная интерпретация).
- Deps: pgvector>=0.3 (ORM Vector). Образ пересобран (pgvector в runtime).

## 2. DoD

- [x] seed-корпус — 7 документов засеяны (`seed`), идемпотентно
- [x] поиск выдаёт релевантные фрагменты — e2e-тест: инжест «Функции и
  return» → запрос «функции return python» → top-1 тот же документ
  (hash-эмбеддер); rag_eval печатает OK/MISS по 6 запросам
- [x] pytest **113+4 passed** · ruff 0 · mypy 0 (111 файлов) — финальный
  прогон после пересборки образа

## 3. Что не сделано / блокеры

- Реальные embeddings (OpenAI-compat) — нет ключа; hash-фолбэк покрывает
  пайплайн, качество на реальной модели мерится rag_eval после подключения
  (R-04 остаётся открытым до тех пор).
- Гибридный поиск (tsv + cosine merge) — tsv-колонка и индекс готовы,
  merge-логика — по факту качества чисто-семантического поиска (S-14+).

## 4. Отклонения от Design (нужны ADR?)

- Нет ADR. ADR-006 (768) соблюдён; модель embedding — конфиг (как предписано
  §10.6/§18.2, финальный выбор — при подключении провайдера).

## 5. Новые факты → Design (обязаны вернуться в Design?)

- hash-фолбэк эмбеддингов — механика dev/CI-режима (echo-аналог из §16.1
  для LLM); зафиксирован в SPEC §3.7. На качество прод-поиска не влияет
  (прод использует модель).

## 6. Риски

- Hash-эмбеддер — наивный bag-of-words: на seed-корпусе релевантен, на
  больших текстах деградирует; R-04 закрывается только реальной моделью.
- HNSW-индекс требует pgvector ≥ 0.5 (в образе pg17+pgvector — свежий) —
  проверено миграцией.
