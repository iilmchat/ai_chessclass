# Отчёт S-58 — Staging-контур и env-контракт

**Дата:** 2026-11-03 · **Этап:** E-21 · **Оценка:** M · **Статус:** ✅

## 1. Что сделано

- **Staging-контур (ADR-014).** `docker-compose.staging.yml` — prod-parity
  стек (11 сервисов: db, redis, migrate, api, worker, 4 per-queue match
  worker'а, web, edge; seed под profile `tools`). Свои имена:
  проект `chessclass-staging`, сеть `chessclass-staging-net`, контейнеры
  `chessclass-staging-*`, volumes `chessclass_staging_*`. Порты хоста:
  pg **5440**, redis **6387**, api **127.0.0.1:8032**, web **3202**,
  edge **8080/8443**; `APP_ENV=staging`, `WEB_BASE_URL=https://localhost:8443`.
  Backend-образ общий `chessclass/backend:${IMAGE_TAG}`; frontend собирается
  с build-arg `APP_STAGE=staging` и тегом `chessclass/frontend:0.3.0-staging`.
- **`.env.staging.example`** — staging-шаблон (порты ADR-014, `CORS_ORIGINS`,
  `WEB_BASE_URL`, `IMAGE_TAG=0.3.0`, секреты `CHANGE_ME_*`, LLM/voice пустые —
  echo-fallback, LRS/Telegram off). `.env.staging` в `.gitignore`.
- **CORS_ORIGINS вместо хардкода.** `core/config.py`: `cors_origins`
  (`Annotated[list[str], NoDecode]`, принимает JSON-массив или список через
  запятую); `app/main.py`: `CORSMiddleware(allow_origins=settings.cors_origins)`,
  в lifespan warning при localhost-источниках в `APP_ENV=staging|prod`.
  Тесты: `tests/test_cors.py` (парсинг env + реальный preflight/ACAO).
- **`.env.staging` — не в проде:** staging-данные изолированы; prod-данные не
  затрагиваются (отдельные volumes/сеть).
- **Runbook:** `docs/runbooks/staging.md` — подъём, migrate/seed, smoke,
  CORS, backup/restore, остановка/сброс, env-дифф dev/staging/prod,
  ограничения.
- **Попутные исправления правды релиза:**
  `/readyz` отдавал версию **0.1.0** из `backend/app/__init__.py` (при
  pyproject/app.main 0.3.0) — исправлено на `0.3.0`, тест
  `test_readyz_details` обновлён;
  e2e redis host-порт **6385→6386** (KI-001: 6385 занят
  `ai-chess-annotator-redis-1`, стенд не поднимался без override).
- **Docs:** Design §2.4 (staging-порты) + §19 ADR-014; RULES §5/§6 (порты,
  каналы запуска); docs/README (runbooks ✅ S-58); TODO_V0.4 S-58 ✅;
  CHANGELOG `[Unreleased]`; README (197 тестов).

## 3. Что не сделано / блокеры

- Живая приёмка LLM/voice/LRS/Telegram — не входит в S-58, это S-59:
  ключей/endpoint нет, режимы echo/hash/off (staging это фиксирует).
- Cookie refresh `Secure=False` при `APP_ENV=staging` (как в dev): для
  https-профиля via edge это допустимо на staging, но не для prod;
  задокументировано в runbook §8.
- HSTS по-прежнему включается только для `APP_ENV=prod` (edge добавляет HSTS
  на staging — проверено smoke); вопрос единой политики — кандидат в S-61.

## 4. Отклонения от Design (нужен ADR?)

- **ADR-014 (добавлен, accepted):** staging-контур с собственными портами
  (pg 5440 / redis 6387 / api 8032 / web 3202 / edge 8080+8443) + e2e redis
  6385→6386 (KI-001). Отклонения от ранее зафиксированного ADR-013 нет —
  dev-порты не менялись.
- Frontend staging-образ отличается от prod только брендом стадии
  (`APP_STAGE`), поэтому тегируется отдельно (`0.3.0-staging`) — чтобы
  staging-сборка не перезаписывала prod-образ под тем же тегом.

## 5. Новые факты → Design (обязаны вернуться в Design?)

- §2.4: staging-порты; §19: ADR-014. Возвращены ✅.
- Контракт `CORS_ORIGINS` (env, comma/JSON) — зафиксирован в конфиге/тестах;
  в Design §15.2 (env-контракт) стоит отразить при следующем обновлении
  Design (S-60 doc-lint). **Не блокер.**

## 6. Риски

- Staging и prod делят тег backend-образа `chessclass/backend:0.3.0`
  (бинарь идентичен, backend не зависит от `APP_STAGE`) — риск низкий;
  при релизе v0.4 tag будет обновлён.
- Self-signed TLS: проверка цепочки не валидируется (`-SkipCertificateCheck`),
  LE/продление — prod runbook.
- Staging-стек локальный: результаты приёмки S-59 не переносятся на prod
  автоматически (политика — S-69).
