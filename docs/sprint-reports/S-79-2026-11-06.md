## 1. Что сделано

- **LRS OAuth2 + Redis (S-79)**:
  - токен `client_credentials` кешируется в Redis (`lrs:oauth:token`,
    TTL до expiry − 60 с), fallback — in-memory для тестов/без Redis;
  - при `401` кэш инвалидируется, токен запрашивается заново и xAPI `PUT`
    повторяется ровно один раз;
  - `lms_sync` (router/worker) передаёт Redis в `sync/deliver_pending`;
  - staging: `LRS_ENABLED/ENDPOINT/OAUTH_*` явно проброшены в
    `docker-compose.staging.yml`, описаны в `docs/runbooks/staging.md`;
  - тест `test_lrs_oauth_refresh_on_401` с `httpx.MockTransport`: IdP
    выдаёт `token-1`, первый PUT — 401, после refresh `token-2` → 204;
    проверены 2 token-запроса, 2 PUT и Redis-кэш.
- **ElevenLabs TTS fallback**:
  - реальный HTTP-вызов уже был; уточнены ошибки: 429 → `voice_quota`,
    прочие HTTP-ошибки → `voice_provider_error`, пустой ключ →
    `voice_unavailable`;
  - все fallback-ответы несут `X-Voice-Fallback: text` (503/429/502),
    проброс заголовка добавлен в `AppError`/`problem_response`;
  - тесты: отсутствие ключа (503 + header), дневная квота (429 + header),
    TTS 429 через fake HTTP client.
- **A11y react-chessboard v5**:
  - `frontend/src/shared/chessA11y.ts` — `squareAriaLabel` и
    `applyBoardA11y` (DOM-патч по `[data-square]`);
  - `ChessPage` оборачивает доску `ref` и обновляет labels после
    FEN/orientation: «Белая пешка на e2», «Пустая клетка e4» и т.п.;
  - e2e `Chess: клетки доски имеют понятные aria-label`;
  - `a11y-axe.spec.ts` уже включает `/chess` в public/authed проходы —
    axe 0 critical/serious; e2e теперь **16 сценариев**.
- **Документы/план**: README/Design/CHANGELOG/SPEC/TODO_V0.6 (S-79 ✅,
  5/6), staging-runbook, этот отчёт.

## 3. Что не сделано / блокеры

Блокеров нет.

Ограничения:

- **Живые LRS/ElevenLabs провайдеры** не вызывались в CI: нет внешних
  credentials; проверены контракты на MockTransport/fake HTTP.
- **A11y-патч завязан на `data-square`** react-chessboard v5; при мажорном
  обновлении библиотеки селектор может измениться — e2e это поймает.
- **TTS fallback — это 503/429 + header**, а не JSON с текстом: UI должен
  показать исходный текст; контракт зафиксирован в SPEC.
- **LRS Redis-кэш** общий для API/воркеров, но при Redis down используется
  in-memory (на один процесс); это допустимый fallback.

## 4. Отклонения от Design (нужен ADR?)

- **`/chess/position` не добавлялся**: в приложении маршрут называется
  `/chess`; axe уже проверяет его в public/authed проходах, e2e проверяет
  aria-label на `/chess`. Отдельный alias не нужен.
- **A11y-патч через DOM** вместо пропсов библиотеки: v5 не даёт
  per-square aria-label; патч минимален и покрыт e2e.
- **TTS 429/502 не превращаются в 200 с текстом**: выбран явный
  HTTP-статус + `X-Voice-Fallback: text`, чтобы UI/клиенты могли
  отреагировать.
- Новый ADR не требуется.

## 6. Риски

- **A11y-патч может сломаться при обновлении react-chessboard**; e2e
  aria-label — регрессионный гейт.
- **TTS-квоты**: 429 от ElevenLabs может быть временным; fallback текстом
  сохраняет UX, но озвучка недоступна.
- **LRS 401-loop**: повтор только один; повторные 401 → failed с backoff,
  чтобы не «долбить» IdP.
- **Кэш токена в Redis**: при компрометации Redis токен до expiry доступен;
  TTL/права Redis и сеть — на операторе.
- **Внешние провайдеры**: live LRS/ElevenLabs требуют staging-ключей и
  мониторинга; в CI проверены только контракты.
- **Aria-label фиксирует русский язык**; при локализации UI потребуется
  передавать locale/строки.
