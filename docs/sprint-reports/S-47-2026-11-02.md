# Отчёт S-47 — Auth-hardening и приватность

**Дата:** 2026-11-02 · **Этап:** E-17 · **Ветка:** main (автономный режим)

## 1. Что сделано

- **RS256/JWKS.**
  - `JWT_ALGORITHM=HS256|RS256`; для RS256 — `JWT_PRIVATE_KEY`/
    `JWT_PUBLIC_KEY` или `*_PATH`, `JWT_KID`.
  - `JWT_LEGACY_HS256=true` — переходный период: старые HS256-токены
    принимаются, новые подписываются RS256.
  - `GET /api/v1/auth/jwks` и `/.well-known/jwks.json`; JWK с `kid/use/alg`.
  - `scripts/gen-jwt-keys.ps1` + `deploy/jwt/` (PEM не в git);
    prod-mount `./deploy/jwt:/srv/jwt:ro`.
  - Decode допускает только настроенный алгоритм + legacy HS256; `none`,
    HS512 и подмена подписи → 401.
- **Аудит auth.**
  - `auth.login.success` (actor user), `auth.login.failed` (emailHash, без
    открытого email), `auth.role.change`, `auth.auditor_scope.change`,
    `auth.user.anonymize`.
  - Роль меняется admin-endpoint; refresh-сессии отзываются.
- **Auditor scope.**
  - `user_profiles.prefs["auditor_scope"]`: `flags`, `audit`, `reports`,
    `observability`; отсутствие ключа = разрешено (обратная совместимость).
  - `require_scope` в auth deps; teacher/admin не ограничены; admin
    управляет через `PATCH /admin/users/{id}/auditor-scope`.
  - Применено к anticheat flags/verdicts, audit logs/CSV, PDF, observability.
- **PII/age_group.**
  - `POST /admin/users/{id}/anonymize`: anon-email, случайный пароль,
    display_name «Удалённый пользователь», age_group unknown, `is_active=false`,
    отзыв refresh; учебные записи остаются для аудита.
  - `age_group` — enum, только самооценка/teacher; без даты рождения.
- **Admin API.** `PATCH /admin/users/{id}/role`,
  `PATCH /admin/users/{id}/auditor-scope`,
  `POST /admin/users/{id}/anonymize`.
- **Тесты.** `test_auth_hardening.py`: RS256/JWKS, legacy HS256,
  none/HS512, role change, auditor scope, anonymize + audit; существующий
  refresh-reuse тест остаётся зелёным.

## 3. Что не сделано / блокеры

- **Реальный внешний IdP/OIDC** не подключался: только собственные JWT/JWKS.
- **Автоматическая ротация ключей** не реализована: скрипт + runbook,
  старый public key держится вручную на время TTL.
- **Auditor scope по классам/школам** не делался: scope доменный
  (flags/audit/reports/observability), не per-class.
- **Полное удаление PII** не выполняется: анонимизация сохраняет учебные
  записи (осознанно, для аудита/отчётности); физическое удаление — backlog.
- **UI управления ролями/scope/anonymize** нет: admin API/Swagger.

## 4. Отклонения от Design

- Legacy HS256 включён по умолчанию для бесшовного перехода; в prod можно
  отключить после истечения старых access-токенов.
- Auditor scope хранится в `user_profiles.prefs`, без новой таблицы/миграции.
- Анонимизация не удаляет пользователя, а деактивирует/обезличивает;
  внешние ключи с CASCADE/SET NULL сохраняют историю.
- JWKS для HS256 возвращает пустой набор (нет публичного ключа).

## 6. Риски

- Legacy HS256 снижает гарантии при компрометации `JWT_SECRET`; отключить
  после перехода.
- Ключи в env/файлах нужно защищать; `deploy/jwt` в gitignore, но
  бэкапы/логи не должны их содержать.
- Scope в `prefs` можно случайно перезаписать через профиль (только self
  prefs; admin scope endpoint аккуратно мержит ключ).
- Анонимизация необратима для email/пароля; нужен подтверждённый процесс.
- JWT `role` claim не используется для авторизации (роль читается из БД),
  это осознанно; после смены роли старые токены не дают старых прав.
