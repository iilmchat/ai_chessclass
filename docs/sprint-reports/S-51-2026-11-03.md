# Отчёт S-51 — PvP-матчи ботов

**Дата:** 2026-11-03 · **Этап:** E-18 · **Ветка:** main (автономный режим)

## 1. Что сделано

- **Схема.** Миграция `0026_pvp`:
  - `pvp_rooms` (code unique, host/guest + bot ids, status, rated,
    tournament_id, timestamps);
  - `pvp_ratings` (отдельный PvP-Elo, wins/losses/draws);
  - `pvp_complaints` (open/reviewed/rejected).
- **Комнаты.** `POST /pvp/rooms`, join по коду, `GET /pvp/rooms/{id}`;
  один активный room на пользователя; активный бот обязателен.
- **Matchmaking.** `POST /pvp/quick-match` ищет waiting-комнату с
  |ΔElo| ≤ 300, иначе создаёт; лимит 10 комнат/quick в минуту → 429.
- **Матч.** `POST /pvp/rooms/{id}/start` создаёт bracket-турнир из двух
  ботов (существующий async-движок S-48) и ставит arq-job; SSE
  `/pvp/rooms/{id}/events`, replay `?matchId`, зрители — любой
  авторизованный пользователь.
- **Рейтинг.** `pvp_ratings` отдельно от лестницы `bot_stats`; Elo K=24,
  старт 1000; tournament-job после завершения обновляет room/rating,
  отмена/ошибка → cancelled/failed.
- **Античит/жалобы.** Наследуется SF-семплирование турнира; участники
  могут подать жалобу, admin/auditor — список `/admin/pvp/complaints`.
- **API/лимиты.** Audit create/join/start/cancel/complaint; leaderboard.
- **Тесты.** Комната/join/start, отдельный рейтинг, leaderboard, жалобы,
  quick-match; fake match-runner без Stockfish.

## 3. Что не сделано / блокеры

- **PvP UI** не делался: API/Swagger + leaderboard; страница может быть
  добавлена в S-55/RC без изменения контрактов.
- **Живой матч** зависит от arq-worker; при остановленном worker комната
  остаётся `running` (recovery турниров S-48 подхватит queued/running).
- **Матчмейкинг** — простой ±300 Elo и waiting-комнаты, без очереди
  Redis и подбора по времени ожидания.
- **Жалобы** только создаются/читаются; статус reviewed/rejected пока
  меняется вручную в БД.
- **Зрители** не ограничены подпиской/классом — любой авторизованный.

## 4. Отклонения от Design

- PvP-матч реализован как bracket-турнир из 2 ботов, а не отдельный
  real-time engine-loop: переиспользует replay/SSE/античит S-48.
- Рейтинг обновляется в tournament-job, а не в API start: результат
  появляется асинхронно.
- Один активный room на пользователя; повторное создание → 409.

## 6. Риски

- Два ученика могут использовать один и тот же bot_version? Нет: active bot
  проверяется по user_id.
- Гонка join/start: `with_for_update` на комнате; room status проверяется.
- Рейтинг обновляется только один раз (`status == done` guard).
- При отмене running-турнира room может получить cancelled, а job —
  завершиться позже; finalize идемпотентен.
- Жалобы не влияют на рейтинг автоматически.
