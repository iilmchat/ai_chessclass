## 3. Что не сделано / блокеры

- **Боевые SMTP/S3-провайдеры не проверены:** SMTP smoke идёт в локальный
  sink, offsite/restore — через encrypted-файл и S3Mock-контур S-93. SPF/DKIM/
  DMARC, bounce, IAM, lifecycle и регион проверяются оператором на стенде.
- **Live LRS/TTS не приняты вживую:** нет боевых ключей LRS/ElevenLabs
  (S-81 остаётся отложенным); проверены mock-контракты и fallback.
- **GPU-туннель не подключён:** нет физической станции RTX 3060 + LM Studio
  (S-84 отложен).
- **Network namespace в песочнице выключен в prod:** `unshare -n` требует
  root/CAP_SYS_ADMIN, worker работает non-root; режим opt-in, альтернативный
  контейнер `network_mode: none` не развёрнут.
- **Полный prod-деплой не выполнялся:** секреты и боевые БД/домены — вне
  репозитория; проверены compose-конфигурация и Docker-контуры.
- **`backup-offsite.ps1` / `backup-restore-test.ps1` с относительным
  `-BackupDir`:** на Windows `docker run -v "backups:/backup"` трактуется как
  named volume, и шифрование/restore падает. В прогоне использован абсолютный
  путь; исправление (resolve absolute path в скриптах) — v0.8.1.

## 4. Отклонения от Design (нужен ADR?)

- **Network namespace — opt-in.** Уже зафиксировано в S-93/Design §13.2;
  отдельный ADR не нужен, это эксплуатационное ограничение non-root worker.
- **pip-audit через OSV** (`-s osv --disable-pip`): `pypi.org` из контейнера
  недоступен; hash-lock не менялся, проверены те же пины. Операционное
  отклонение, ADR не нужен.
- **Локальный CI потребовал пересборки `chessclass/backend:dev`:** в образе
  до пересборки не было S-93-изменений (non-root `appuser`, PATH с
  user-site), из-за чего `pip install --user` ставил ruff вне PATH. После
  `docker compose build api` гейты прошли; кода релиза это не касается.
- **Абсолютный `-BackupDir` при restore-прогоне:** обход бага относительного
  пути (см. §3), не архитектурное отклонение; исправление планируется в
  патче.

## 6. Риски

- **Prod-деплой без боевых ключей.** SMTP обязателен — без него блокируется
  email-верификация; без `BACKUP_S3_*`/`BACKUP_ENCRYPTION_KEY` бэкапы не
  уходят offsite. Чек-лист оператора — в release-notes.
- **Отсутствие live-приёмки LRS/TTS.** Контракты и fallback проверены, но
  реальные OAuth2/квоты/латентность провайдеров не подтверждены.
- **Network ns не активен.** Сетевой слой песочницы держится на AST/builtins
  и opt-in-флаге; для сильной изоляции нужен отдельный sandbox-контейнер.
- **Относительный `BackupDir`.** До патча v0.8.1 запускать offsite/restore
  с абсолютным путём; иначе backup завершится ошибкой (данные не потеряются,
  но алерт `ChessClassBackupFailed` сработает).
- **S3Mock ≠ боевой S3, локальный SMTP ≠ провайдер.** Первый боевой
  backup/restore и SMTP-письмо — обязательный smoke на стенде.
- **Ключи и секреты.** `BACKUP_ENCRYPTION_KEY`, S3-ключи, `SMTP_PASSWORD`,
  `SENTRY_DSN` не логируются и не коммитятся; `CHANGE_ME_*` в примерах
  сохранены.
