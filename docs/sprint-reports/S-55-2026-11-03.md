# Отчёт S-55 — Нагрузка, доступность и безопасность

**Дата:** 2026-11-03 · **Этап:** E-20 · **Ветка:** main (автономный режим)

## 1. Что сделано

- **Нагрузка.** `backend/scripts/load_smoke.py` (httpx, concurrency,
  p50/p95, exit code). Dev 30 запросов / 5 concurrency: p95 **76 мс**,
  ошибок 0; `/readyz` отдельно ~500 мс (DB/Redis). Профиль и целевые p95
  в `docs/load-profile.md`.
- **A11y.** Skip-link к `#main`, глобальный `:focus-visible`, aria-label
  полей/навигации, consent-label; чеклист `docs/a11y-audit.md`.
- **Security.**
  - middleware security headers: nosniff, frame DENY, referrer no-referrer,
    permissions-policy, HSTS при `APP_ENV=prod`;
  - `pip install --upgrade pip` в Dockerfile (устранены 12 vuln pip 25.0.1);
  - `pip-audit` — no known vulnerabilities (проект skip, не PyPI);
  - secrets scan tracked files — совпадений нет;
  - OWASP-чеклист и остаточные риски — `docs/security-review.md`.
- **Тест.** `test_security_headers.py`; backend **195 passed**.

## 3. Что не сделано / блокеры

- **Матчи/турниры/LLM** не нагружались: нужен worker+SF и внешний LLM;
  профиль вынести на staging в S-56.
- **axe-core/playwright** не добавлены; a11y — ручной чеклист.
- **CSP** не включён: требует аудита Vite inline/asset.
- **pip hash-lock/constraints** отсутствует; supply-chain риск.
- **Egress allowlist** для LLM/LRS/Telegram не настроен.
- **`aria-live`** не на всех страницах (Profile/Review).
- **Контраст** muted/dark не проверен инструментом.

## 4. Отклонения от Design

- Security headers добавлены middleware, а не reverse-proxy: работают и в
  dev, HSTS только prod.
- Load smoke — health-only по умолчанию; readyz включается флагом, чтобы
  DB/Redis ping не искажал p95 health.
- pip обновляется в Dockerfile, а не фиксируется версией; для RC нужен
  lock/constraints.

## 6. Риски

- Dev p95 на одном uvicorn-worker не отражает prod-кластер; readyz
  зависит от DB/Redis.
- Security headers не заменяют CSP/egress-контроль.
- pip-audit проверяет текущий контейнер, не финальный RC-образ.
- a11y-проверка не автоматизирована — регрессии возможны.
- HSTS включается только в prod; за TLS отвечает reverse-proxy.
