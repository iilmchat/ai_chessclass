## 4. Отклонения от Design (нужен ADR?)

- **Маскировка сделана wrapper'ом, а не `log_config`.** Alertmanager 0.28 не
  поддерживает log-фильтры/`log_config` с redaction; поэтому entrypoint
  направляет логи через `redact-logs.awk`. Это продолжение ADR-021, отдельный
  ADR не требуется; последствия и ограничения внесены в ADR-021.
- **Выбран email, а не webhook.** Задача допускала оба варианта. Email
  переиспользует SMTP S-75, не добавляет новый HTTP-эндпоинт с токеном и
  проще проверяется; webhook потребовал бы API-контракт, аутентификацию и
  защиту от флуда. Email включается условно, чтобы не ломать S-82-развёртывания
  без SMTP.
- **Selftest не считает down `chessclass-api` ошибкой профиля.** Профиль
  observability можно проверять без базового стека; target `chessclass-api`
  обязан присутствовать в конфиге, но его `down` — информационный вывод, а не
  FAIL. Иначе `-Stack` на чистом стенде даёт ложный отрицательный результат.
- **Уникальное имя тестового алерта.** Из-за персистентного nflog повторный
  selftest с тем же alertname ждал `repeat_interval`; имя теперь содержит
  время. Это тестовая деталь, продуктовые маршруты не менялись.
- **Исправлена опечатка в `TODO_V0.4.md`** (слитное «изолированном»+«e2e»
  → с пробелом) — гигиена алфавитов; содержательных правок нет.
- Новый ADR не требуется: S-87 расширяет ADR-021.

## 6. Риски

- **Узкий шаблон маскировки.** URL-encoded или иной формат токена может не
  совпасть; логи всё равно считать чувствительными, не выгружать в общий SIEM
  без дополнительной фильтрации, TTL 14 дней. При подозрении на утечку —
  перевыпуск токена BotFather.
- **Email требует STARTTLS (587).** Implicit TLS 465 не поддерживается; для
  465 нужен relay. Реальная доставка зависит от SMTP-провайдера и allowlist;
  при недоступности SMTP Telegram продолжает работать (маршруты независимы).
- **`node-exporter` видит volumes, а не весь host root.** Алерт ловит
  заполнение диска, на котором лежат volumes observability; другие разделы
  хоста (логи, бэкапы, БД) он не покрывает. Если `node-exporter` не
  скрейпится, алерт по диску молчит — нужен контроль target `node-exporter`
  (S-88 может добавить meta-alert).
- **At-least-once для email.** Если SMTP принял письмо, а соединение оборвалось
  до подтверждения, Alertmanager повторит отправку; дубль письма возможен.
- **Selftest использует фиктивный токен и локальный SMTP.** Боевые Telegram/SMTP
  проверяются при развёртывании; selftest не заменяет приёмку каналов.
- **nflog Alertmanager персистентен.** При ручной проверке с тем же alertname
  повторная доставка может ждать `repeat_interval`; для тестов использовать
  уникальное имя (как в selftest).
- **Секреты в sed-подстановке.** Значения с переводом строки/NUL не
  поддерживаются (ограничение env); пароли с `\ & | "` экранируются.
- **Docker-логи Alertmanager** ограничены только для этого сервиса; внешние
  сборщики логов могут хранить дольше — TTL задаётся политикой оператора.
