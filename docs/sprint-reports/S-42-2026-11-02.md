# Отчёт S-42 — Достижения, стрики и age_group

**Дата:** 2026-11-02 · **Этап:** E-15 · **Ветка:** main (автономный режим)

## 1. Что сделано

- **Схема.** Миграция `0018_progress`:
  - `user_profiles.age_group` (`child|teen|adult|unknown`, default `unknown`);
  - `py_progress` — `solved_count`, `topics jsonb`, `solved_assignments jsonb`,
    `current_streak`, `longest_streak`, `last_solved_on`, `updated_at`;
  - `achievements` — каталог бейджей (`code`, `kind`, `threshold`, `icon`);
  - `user_achievements` — PK `(user_id, achievement_id)` → бейдж один раз,
    `awarded_at`, `context jsonb`.
- **Стрики (`domains/progress/service.py`).**
  - Первый уникальный passed-ассайнмент в новый день: +1.
  - Если последний день — вчера: продолжение; иначе сброс в 1.
  - Повторное решение того же задания не меняет счётчик/стрик.
  - `longest_streak` сохраняет максимум.
  - Хук в `python_teacher.submit` после успешной сдачи (только student).
- **Бейджи.** Seed 6 штук: first/five/ten solutions, streak_3/7,
  topics_3. Выдача идемпотентна (PK + проверка), событие пишется в
  `audit_logs` (`achievements.award`, source `system`).
- **API.** `GET /progress/me` и `GET /progress/{user_id}`
  (teacher/admin) — решено, темы, current/longest streak, каталог бейджей
  с `awarded/awardedAt`.
- **age_group.** `ProfileOut.ageGroup`, `PATCH /profile/me { ageGroup }`;
  безопасный default `unknown`, без даты рождения; меняет сам пользователь.
- **UI `/profile`.** Аккаунт + возрастная группа, прогресс (решено, темы,
  стрики), каталог достижений (получен/закрыт), дата получения.
- **Тесты.** `tests/test_progress.py`: рост/сброс стрика, повтор задания,
  one-time бейджи, age_group PATCH, прогресс после реальной сдачи.

## 3. Что не сделано / блокеры

- **`chess_progress`** (шахматные стрики/blunder-серии) не добавлялся:
  S-42 сфокусирован на `py_progress`; шахматный прогресс можно добавить
  отдельным срезом.
- **Уведомления о бейджах** (SSE/push) не делались: событие в аудите +
  отображение в профиле; push — backlog.
- **Динамические/сезонные бейджи** — каталог статический seed; редактор
  бейджей не делался.
- **Возрастная группа** — самооценка, без проверки; для школы достаточно,
  но для отчётности нужна валидация учителем (backlog).
- **Стрик по часовому поясу** считается по UTC-дате; для учеников в
  другом TZ возможен сдвиг дня — зафиксировано.

## 4. Отклонения от Design

- `achievements` — каталог + `user_achievements`, а не одна таблица
  «бейджи»: нужна идемпотентность и метаданные выдачи.
- `solved_assignments` хранится в `py_progress` (JSONB), чтобы не
  дублировать проверку `py_submissions`; при росте — нормализовать.
- `age_group` — enum-строка, не дата рождения (PII-минимизация).
- Стрик считается по **уникальным** заданиям, не по числу сдач.

## 6. Риски

- JSONB `solved_assignments` растёт с числом заданий; для v0.2 нормально,
  при 1000+ — отдельная таблица `py_solved`.
- Стрик по UTC может «ломаться» у учеников в UTC+; нужен TZ в профиле
  или считать по локальной дате (backlog).
- Бейджи выдаются в транзакции сдачи; при откате сдачи откатятся и
  бейджи — это корректно, но нужно следить за размером транзакции.
- `age_group` — чувствительные данные; не логировать в LLM/аудит meta.
