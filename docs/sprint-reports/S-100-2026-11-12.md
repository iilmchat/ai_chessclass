## 6. Риски

- Приёмка может выявить блокер провайдера (SMTP-репутация домена, S3
  lifecycle, GPU-туннель) — тогда релиз v1.0.0 сдвигается, блокер
  фиксируется в S-101.
- v1.0.0 с незакрытым S-95 допустим только по письменному решению
  владельца (известное ограничение), иначе релиз не выпускается.

## 7. Следующий спринт — S-101: Release v1.0.0

v1.0.0 выпускается **только после** успешной staging acceptance S-100:

1. `staging-acceptance.ps1` не вернул `2` (critical), P0-чеки
   `final-acceptance.md` отмечены; отчёт оператора сохранён.
2. GPU-станция отвечает через `test-gpu-tunnel.ps1` (chat + ток/с,
   exit 0), fallback cloud → local → echo проверен.
3. Observability: `observability-selftest.ps1 -Stack` зелёный, critical
   алертов нет.
4. S-95 подтверждён live **или** владелец письменно зафиксировал live
   LRS/TTS как известное ограничение v1.0.0.
5. Затем — версия `1.0.0` во всех источниках, release notes, CHANGELOG,
   doc-lint `CURRENT_VERSION=1.0.0`, бейдж **Production Ready**, тег
   `v1.0.0` и GHCR-образы.

При провале любого условия — блокер в S-101 и повторная приёмка после
устранения.
