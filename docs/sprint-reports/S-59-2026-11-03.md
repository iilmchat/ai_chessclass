(часть 1 закрыта; live-прогон — после появления ключей LLM/voice)

## 1. Что сделано

- **`backend/scripts/llm_smoke.py` v2** (был live-only с S-31):
  - `--mode auto|echo|live`: `auto` — live при настроенном провайдере, иначе
    echo; echo-режим детерминированно гасит провайдера
    (`settings.llm_base_url=""` + `close_llm_providers()`), поэтому baseline
    не зависит от окружения;
  - `--with-voice` (S-44) и `--with-pdf` (S-25): без `VOICE_API_KEY` озвучка
    ожидаемо `disabled` (graceful `voice_unavailable`), PDF генерируется
    локально (fpdf2 + DejaVu) и проверяется по `%PDF-`;
  - `--out PATH` — JSON-артефакт schema `chessclass.llm_smoke/1`
    (провайдер, health, кейсы, voice, pdf, FinOps, ожидания, verdict);
  - `--compare PATH` — per-route diff echo→live (status/model/cost,
    head-summary); при чужой схеме — generic-сравнение без исключений;
  - health провайдера in-process (аналог `/admin/llm/health`): ok/degraded/echo,
    `missingModels`, latency `list_models` ≤5 с;
  - FinOps: новые строки `llm_calls` (route/status/model/tokens/cost/latency)
    + суммы за UTC-сутки; echo обязан дать `cost=0`;
  - коды возврата: **0** — ожидания выполнены; **2** — расхождение
    (route/health/voice/pdf); **3** — конфигурация (live без провайдера,
    нет БД/Redis/записи артефакта).
- **Тесты:** `backend/tests/test_llm_smoke.py` — 3 unit-теста на чистые
  хелперы (`_expected_case_status`, `_summarize_calls`, `_compare_artifacts`,
  включая generic-fallback). Итого backend: **200 passed**, ruff/mypy 0
  (240 файлов).
- **Документация:** `docs/runbooks/llm-gateway.md` §2.2 (echo→live,
  `--compare`, коды, staging-примеры), `docs/runbooks/staging.md` §4
  (команда smoke на staging).

## 6. Риски

- Echo-базлайн снимается при принудительно погашенном провайдере — если в
  staging появятся ключи, `--mode auto` начнёт гонять live; для baseline
  всегда указывать `--mode echo` (документировано).
- Live-цены/бюджеты: сверка опирается на `llm_calls.cost_*` и
  `BUDGET_FREE_TOKENS_DAY`; при смене каталога цен обновить `LLM_COST_*`
  (runbook §3) — иначе diff цен будет неинформативным.
- `--with-voice` тратит дневную квоту символов на staging (кэш TTS
  переиспользуется) — для повторных прогонов учитывать `voice:chars:*`.

## 7. Следующий шаг — live-приёмка (когда появятся ключи)

```powershell
# 1) ключи в .env.staging (не в git): LLM_BASE_URL, LLM_API_KEY, LLM_MODEL_*,
#    LLM_COST_*; для TTS — VOICE_API_KEY
docker compose --env-file .env.staging -f docker-compose.staging.yml up -d
docker compose --env-file .env.staging -f docker-compose.staging.yml exec -T api `
  python scripts/llm_smoke.py --mode live --with-voice --with-pdf `
  --out /srv/reports/llm-smoke-live.json `
  --compare /srv/reports/llm-smoke-echo.json
# ожидаемо: exit 0, 4/4 status=ok, health=ok, cost>0, diff echo -> live
```
