# Отчёт S-40 — Группы и классы

**Дата:** 2026-11-02 · **Этап:** E-15 · **Ветка:** main (автономный режим)

## 1. Что сделано

- **Схема.** Миграция `0015_classes`:
  - `classes(id, name, teacher_id → users, invite_code UNIQUE, created_at)`;
  - `class_members(class_id → classes, user_id → users, joined_at)`,
    PK `(class_id, user_id)`;
  - индексы `ix_classes_teacher`, `ix_class_members_user`.
- **Домен `domains/classes`.**
  - `POST /classes` — teacher/admin создаёт класс, получает инвайт-код.
  - `GET /classes` — teacher видит свои, student — членство, admin — все.
  - `POST /classes/join` — student по коду; повторный join идемпотентен.
  - `GET /classes/{id}` — manager/member; roster отдаётся только manager.
  - `POST /classes/{id}/invite` — ротация кода владельцем/admin.
  - `POST /classes/{id}/members` — добавление ученика по email.
  - `DELETE /classes/{id}/members/{userId}` — удаление ученика.
  - `GET /classes/{id}/dashboard` — групповой срез.
- **RBAC.** Owner-teacher или admin; чужой teacher получает 403
  `class_forbidden`; student не создаёт класс (403) и не видит дашборд;
  join — только student; чужой/несуществующий код — 404.
- **Дашборд.** По каждому ученику: 11 навыков (EMA), флаги
  (`flagsCount`/`newFlagsCount`), матчи/победы/поражения/ничьи/Elo из
  `bot_stats`; `joinedAt`, уровень, displayName.
- **Seed.** Добавлен `teacher@chessclass.dev` / `dev-teacher-2026`
  (`SEED_TEACHER_PASSWORD`), чтобы кабинет учителя был доступен в dev.
- **UI `/classes`.** Список классов, создание, инвайт-код с ротацией,
  добавление/удаление учеников, таблица группы (слабые навыки, флаги,
  матчи/Elo); для ученика — join по коду и список своих классов.
- **Тесты.** `tests/test_classes.py`: create/join/dashboard; чужой teacher
  403 на detail/dashboard/mutations; add/duplicate/remove/rotate; student
  не создаёт класс и не видит дашборд.

## 3. Что не сделано / блокеры

- **Email-инвайты** не отправляются: используется код класса + добавление
  по email. SMTP в v0.1 отсутствует; для v0.2 код достаточен.
- **Архивирование/удаление класса**, переименование, лимиты на количество
  классов — не входили в S-40; можно добавить в S-41/S-42.
- **Фильтры дашборда** (низкие навыки/Elo) и экспорт CSV — S-41 (auditor)
  и дальнейшие; сейчас сортировка слабых навыков на клиенте.
- **Массовый импорт учеников** — не делался.
- **Роль teacher через UI** не создаётся: seed + admin/DB; управление
  пользователями — вне S-40.

## 4. Отклонения от Design

- Инвайт — код на классе, а не отдельная таблица приглашений: проще,
  идемпотентно, соответствует «инвайтам» S-40.
- Roster в `GET /classes/{id}` отдаётся только manager; student видит
  класс и счётчик, но не список одноклассников (privacy by default).
- Dashboard агрегирует **все 11 навыков** (не только chess): учитель видит
  общий профиль; фильтры — следующий шаг.

## 6. Риски

- `invite_code` — 8 символов из 32-буквенного алфавита (~40 бит):
  достаточно для школьного класса, но код можно перебирать; rate-limit
  на join стоит добавить при публичном доступе.
- Дашборд делает N+1 запросов навыков по ученикам; для класса ≤30
  приемлемо, при росте — один агрегирующий запрос.
- Добавление по email раскрывает факт существования пользователя (404 vs
  403); для закрытого школьного контура допустимо.
- Нет архивирования: удаление учителя каскадно удаляет классы/членство;
  для prod нужна политика бэкапов (S-38 уже есть).
