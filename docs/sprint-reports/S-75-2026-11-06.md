## 3. Что не сделано / блокеры

Блокеров нет.

Ограничения:

- **Реальный SMTP-провайдер** не проверялся: тест использует fake SMTP;
  перед prod нужен прогон на staging с боевым ящиком (SPF/DKIM/DMARC).
- **HTML-шаблоны** писем не делались: только plain text (достаточно для
  ссылок и соответствует текущему verify-email).
- **Retry/очередь писем** нет: при временном сбое SMTP consent-запрос
  возвращает 502 и требует повтора пользователем.
- **Enforcement не включает admin/auditor export**: это осознанно —
  правовое основание аудита; если школа хочет иначе, нужна политика/ADR.
- **Возраст по-прежнему декларируется** учеником; подтверждение учителем —
  в backlog S-76+.

## 4. Отклонения от Design (нужен ADR?)

- **SMTP-транспорт — реализация ADR-019**, отдельный ADR не нужен.
- **PDF/LLM gate — уточнение ADR-019**: enforcement сделан на уровне
  gateway/PDF, а не в каждом роутере; это единая точка и меньше риска
  забыть проверку.
- **Экспорт не блокируется** — трактовка GDPR/аудита: admin/auditor
  обрабатывает данные по правовому основанию, а не по продуктовому
  согласию; зафиксировано в SPEC/Design.
- **Doc-lint переведён на TODO_V0.6** — иначе активный план v0.6 нельзя
  проверить; инструмент, не архитектура.

## 6. Риски

- **Deliverability**: без SPF/DKIM/DMARC письма родителям могут попадать в
  спам; нужен staging-прогон и мониторинг bounce.
- **PII в email**: письмо содержит ссылку-токен, но не данные ребёнка;
  логи dev содержат ссылку — не включать prod-логи с токеном.
- **SMTP-секреты** — env/secret manager, не в репозитории; ротация.
- **Блокировка LLM** может восприниматься как поломка: UI должен вести в
  `/consent`; сейчас ошибка отображается, отдельный CTA — кандидат S-76.
- **Возраст/родитель** по-прежнему self-declared + possession of token;
  для строгого COPPA нужна верификация родителя/учителя.
- **SMTP без retry** — временные сбои требуют ручного повтора; очередь
  писем — backlog.
