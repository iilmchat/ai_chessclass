# Отчёт S-41 — Роль auditor и журнал аудита

**Дата:** 2026-11-02 · **Этап:** E-15 · **Ветка:** main (автономный режим)

## 1. Что сделано

- **Роль `auditor`.** `UserRole.AUDITOR`; миграция `0016_audit` расширяет
  CHECK `users.role` до `student/teacher/admin/auditor`. Seed:
  `auditor@chessclass.dev` / `dev-auditor-2026`.
- **`audit_logs`.** Миграция + ORM `domains/audit/models.py`:
  `actor_id` (FK SET NULL), `actor_email/actor_role` — снимок на момент
  действия, `action`, `target_type/id`, `source`, `meta jsonb`,
  `request_id`, `created_at`; индексы actor/created/action.
- **Запись.** `domains/audit/service.record` пишет в той же транзакции,
  что и действие. Логируются:
  - классы: `classes.create/join/invite.rotate/member.add/remove`;
  - античит: `anticheat.flag.review`, `anticheat.judge.verdict`;
  - PDF: `reports.pdf.generate/download`;
  - экспорт: `audit.export`.
- **Чтение/экспорт.**
  - `GET /admin/audit/logs` — фильтры `actorId`, `action`, `targetType`,
    `source`, `dateFrom/dateTo`, пагинация; teacher/admin/auditor.
  - `GET /admin/audit/export.csv` — те же фильтры, UTF-8 BOM, лимит
    10 000 строк, `Content-Disposition: attachment`.
- **RBAC.** Auditor читает `GET /admin/anticheat/flags`,
  `GET /admin/anticheat/judge`, `GET /admin/anticheat/students/{id}/card`,
  `GET /reports/pdf/{id}`, audit logs/CSV. Мутации (review флага/вердикта,
  генерация PDF, классы) — 403 `auth_forbidden`.
- **Фикс схемы.** `reports_pdfs.requested_by` был `NOT NULL` при FK
  `ON DELETE SET NULL` — удаление учителя с PDF падало. Миграция
  `0017_reports_requested_by_null` + модель приведены в соответствие.
- **Тесты.** `tests/test_audit.py`: действия учителя попадают в журнал;
  фильтр/пагинация; auditor читает флаги/вердикты/PDF/CSV; auditor не
  меняет; student не читает журнал; экспорт логируется.

## 3. Что не сделано / блокеры

- **UI журнала аудита** не делался: API + CSV + Swagger; для S-41
  достаточно, экран можно добавить в S-42/дальше.
- **Retention/партиционирование `audit_logs`** не настроены: журнал
  растёт; для prod нужна политика (например, 1 год + архив).
- **Логирование аутентификации/логинов** не включено: фокус на
  «чувствительных действиях» учителя/аудитора; можно добавить отдельно.
- **Аудит чтения** (кроме PDF/CSV) не пишется, чтобы не раздувать журнал;
  спорный компромисс, зафиксирован.
- **Иммутабельность** обеспечена только на уровне API (нет update/delete
  endpoints); прямой SQL/админ БД может изменить — для v0.2 приемлемо.

## 4. Отклонения от Design

- Журнал доступен не только auditor, но и teacher/admin (для разбора
  инцидентов); auditor — read-only.
- CSV-экспорт ограничен 10 000 строк (защита от выгрузки всей БД);
  фильтры позволяют сузить выборку.
- `actor_email/role` денормализованы: после удаления пользователя
  `actor_id` обнуляется, но история остаётся читаемой.
- PDF-просмотр разрешён auditor; генерация — только teacher/admin.

## 6. Риски

- Рост `audit_logs` без retention; нужен cron/архив (S-38 backup уже
  покрывает дампы, но не retention журнала).
- В `meta` могут попасть чувствительные данные (email, заметки); не
  писать пароли/токены — ответственность вызывающего кода.
- Auditor видит все PDF/флаги; при расширении школы нужен scope по классам.
- CSV с PII: скачивание логируется, но файл не защищён — хранить в
  защищённом месте.
