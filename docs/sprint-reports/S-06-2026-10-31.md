# Отчёт S-06 — Промпты уровня (prompt_builder)

**Дата:** 2026-10-31 · **Этап:** E-02 LLM-шлюз (завершён) · **Статус:** ✅

## 1. Что сделано

- `llm/prompts/levels.py` — правила уровней (порт levels.py из teacher +
  §5.5): novice — без готового решения (наводящие вопросы, шаги, синтаксис
  на отвлечённом примере); intermediate — причины, фрагменты, мини-упражнение;
  advanced — терминология, сложность, альтернативы, полное решение; флаг
  `gives_ready_code`.
- `llm/prompts/templates.py` — роль для каждого из 10 маршрутов (RU),
  `build_system_prompt` (роль + правила уровня + формат «markdown, краткие
  факты отдельно»), `PROMPT_VERSIONS` (изменение текста → +1 и тест).
- `llm/prompts/builder.py` — `build_messages(route, level, request, facts,
  history)`: system → история (последние 20, обрезка 4000 симв. — порт
  констант teacher) → user (запрос + блок фактов «менять нельзя»);
  `ROUTE_PARAMS` — temperature/max_tokens по маршруту (таблица → SPEC §6.5).
- Тесты (+9): comment/hint промпты различаются по уровню (DoD), insight
  с блоком фактов, полнота таблиц (params/versions/roles == маршруты),
  judge с низкой температурой, лимиты контекста, echo-сквозной тест
  собранного промпта.

## 3. Что не сделано / блокеры

- Файловое хранение промптов (teacher: `prompts/<level>.txt` + versions.json)
  — в v0.1 шаблоны в коде (один модуль, тесты прямые); вынос в файлы —
  при появлении непрограммного редактирования промптов (v0.2).
- Стриминг ответов (WebSocket/SSE для чата) — не в объёме S-06 (§14.2
  интерактивные экраны появятся в E-03+).

## 4. Отклонения от Design (нужны ADR?)

- Нет ADR. Структура ответа «markdown + краткие факты отдельно» (§8.6)
  зафиксирована в FORMAT_RULES; таблица параметров — SPEC §6.5 (как
  предписывает §8.2 «итоговая таблица — в docs/SPEC.md»).

## 5. Новые факты → Design (обязаны вернуться в Design?)

- Temperature/max_tokens по маршрутам — новые факты (Design их не задавал,
  только «таблица в SPEC») —SPEC §6.5 заполнен; Design правки не требует.

## 6. Риски

- Тексты шаблонов — первая редакция: живая калибровка после реальных
  вызовов RouterAI (S-07+, когда появятся сдачи/инсайты); версии позволят
  отслеживать дрейф.
- Оценка длины контекста в символах, а не токенах (порт teacher) — для
  RouterAI может понадобиться токенизаторная точность; заметно на длинных
  партиях (E-04) — там и поправим.
