# Отчёт S-17 — Контракт и SafePosition (bot_lab)

**Дата:** 2026-11-01 · **Этап:** E-07 Лаборатория ботов · **Статус:** ✅

## 1. Что сделано

- Миграция `0011_bot_versions` (user, version_no растёт per user, code,
  entry, is_active).
- `safe_position.py` — read-only фасад над chess.Board: fen, turn
  (white/black), legal_moves (UCI), is_check, piece_at, is_attacked,
  material (пешечные единицы), king_square.
- `runner.py` — собственный subprocess-раннер бота: SafePosition строится
  в дочернем процессе (`extra_globals` в run_restricted — расширение
  ядра песочницы), entry вызывается после решения ученика, ход печатается
  солёным… (фикс. маркером) и **валидируется родителем** (легальность).
  per-move таймаут `BOT_PERMOVE_TIMEOUT_S=1.0`, RLIMIT 256 МБ, async-обёртка.
- `service.py` — версии (version_no autoincrement per user), test_move с
  маппингом ошибок (`bot_restricted` 422 / `bot_timeout` 408 / `bot_error`).
- Роутер `/api/v1/bots`: GET список (свои активные), POST создать, GET
  bot, POST /test.
- **`chess` в FORBIDDEN_MODULES** песочницы (TODO: «запрет python-chess
  внутрь») — ботам SafePosition вместо библиотеки.

## 2. DoD

- [x] простой random-бот ученика возвращает легальные ходы — тест:
  `random.choice(position.legal_moves)` → ok, UCI из 20 стартовых
- [x] нарушения: `import chess` → bot_restricted; while True → bot_timeout
  (408); нет return → bot_error (ContractViolation); чужой бот → 404
- [x] pytest **132 passed** · ruff 0 · mypy 0 (124 файла)

## 3. Что не сделано / блокеры

- `evaluate(position)->float` — контракт зафиксирован (entry), greedy-бот
  на нём — S-18 (лестница).
- UI ботов (редактор кода) — с матчами (S-19/S-20), до того API-first.

## 4. Отклонения от Design (нужны ADR?)

- Нет ADR. Run бота — свой subprocess-раннер поверх ядра sandbox.runtime
  (executor teacher — «общий, не копия»: ядро общее, раннеры разные
  по необходимости — SafePosition требует доверенный объект в ребёнке).

## 5. Новые факты → Design (обязаны вернуться в Design?)

- Правило расширено: **генерируемый код для RP не содержит `_`-имён**
  (третий случай — `_move` в раннере бота); вынесено в правило §2 RULES
  ранее (S-08) — подтверждается.
- `chess` в запретах песочницы — новый факт → SPEC §7/§3.9 (внесено).

## 6. Риски

- Per-move subprocess ~0.3-0.5 с накладных — матч на 60 полуходов двух
  ботов ≈ 60-80 с только на spawn; S-18 решает пулом/батчем (teacher S-23).
- SafePosition раскрывает legal_moves списком строк — для 40+ фигурных
  позиций объём умеренный; при необходимости добавлю ленивый итератор.
