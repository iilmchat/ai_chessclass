# Отчёт S-64 — RAG-редактор UI и gold-set eval

**Дата:** 2026-11-03 · **Этап:** E-23 Продуктовая полнота · **Статус:** ✅

## 1. Что сделано

- Страница **`/rag`** (frontend/src/pages/RagEditorPage.tsx), доступ
  teacher/admin (гвоздь по роли из `/profile/me`; вход через тот же
  LoginGate): 
  1. список документов с фильтром по статусу (draft/published/archived);
  2. **редактор** — создание черновика, правка → новая версия
     (title/domain/kind/license/text, save → PATCH/POST);
  3. панели **версий** документа с «В редактор» и **rollback**;
  4. **импорт** файлом (.md/.markdown/.txt/.pdf → FileReader → base64 →
     draft, license);
  5. **поиск-превью** топ-5 (published, similarity/lexical);
  6. панель **eval** (gold-set, baseline/hybrid/passed) с таблицей кейсов.
- Навигация: `/rag` «RAG-база» в топбаре; CSS — `.rag-*` классы.
- **Gold-set 3→21 кейс** — `backend/rag/eval_cases.py` (пары
  «запрос → эталонная подстрока» от сид-корпуса 17 документов: 7 python +
  10 chess; проверены sentinel-скриптом `scripts/rag_gold_check.py` —
  «все подстроки в corpus (published)» — это защищает от мёртвых кейсов);
  `GET /admin/rag/eval` — таблица `results` по каждому кейсу
  (vectorHit/hybridHit) + прежние поля (baseline/hybrid/passed/cases).
- Тесты: `test_eval_gold_set_min_20_cases` (+1) — cases ≥ 20, порядок,
  типы. Backend: 220 passed (локальный), ruff/mypy 0.
- Frontend: tsc+vite build (83 модуля) — зелёный; vitest 5/5.

- DTO `EvalOut.results` — additive-расширение контракта §3.25 (S-64).

## 6. Риски

- 21 кейс × 2 режимов × k5 retrieval — eval-запрос на ~2-3 с (локально/CI);
  на большой базе — кэш результатов (S-69-полировка).
- Hash-эмбеддинг baseline — слаб по семантике; переход на реальную модель
  изменит и baseline, и hybrid (eval — регресс-сторож, не абсолют).
