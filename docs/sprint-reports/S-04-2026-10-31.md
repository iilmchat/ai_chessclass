# Отчёт S-04 — LLM Gateway core

**Дата:** 2026-10-31 · **Этап:** E-02 LLM-шлюз · **Статус:** ✅

## 1. Что сделано

- Пакет `backend/llm/` (Design §8, §3.3):
  - `base.py` — контракт провайдера (порт `app/services/llm/base.py` из
    teacher: LLMMessage/LLMUsage/ошибки/is_placeholder_secret);
  - `client.py` — OpenAI-совместимый httpx-клиент (base URL/key из env,
    таймаут 40 с, 1 retry через 2 с — §8.4; транспорт инъекцируется);
  - `models_registry.py` — 5 тиров (L1/L2/L3/L3_alt/judge), слаги из env,
    цены ₽/1M Numeric(12,4) из env (Design §8.3);
  - `routes.py` — 10 маршрутов v0.1 с advanced-переопределениями (§8.2);
  - `gateway.py` — `LLMGateway.generate(route, level, messages)` → текст+usage;
  - `bootstrap.py` — сверка слагов с `GET /models` провайдера (R-01):
    несуществующий → warning + автопропуск; вызов в lifespan;
  - `router.py` — `GET /api/v1/admin/models` (admin, Design §12.2
    «модели/цены readonly»).
- Config/env: `LLM_MODEL_L3_ALT`, `LLM_TIMEOUT_S=40`, `LLM_RETRY_DELAY_S=2`,
  `LLM_COST_{L1,L2,L3,L3_ALT,JUDGE}_{IN,OUT}` (дефолты — из Design §8.3).
- Документация: SPEC §6 (маршруты/модели/API) + история, CHANGELOG (S-04).

## 4. Отклонения от Design (нужны ADR?)

- Нет ADR. Дефолтные слаги моделей зафиксированы в config/env как
  «ожидаемые» (R-01 их сверяет; несоответствие → warning + env-правка) —
  это ровно механизм §8.3.
- `list_models` транспорта не входит в ABC контракта провайдера teacher —
  добавлен метод (нужен бутстрапу); отражено в SPEC §6.

## 5. Новые факты → Design (обязаны вернуться в Design?)

- httpx сериализует JSON компактно (`{"model":"x"}`) — учтено в тестах;
  деталь реализации, в Design не дублируется.
- L3_alt/judge цены — «(…)» в §8.3 → реализованы как nullable Decimal,
  заполняются env (`LLM_COST_L3_ALT_*`, `LLM_COST_JUDGE_*`); формат совпадает.

## 6. Риски

- Слаги RouterAI — предположения (R-01): при получении ключа бутстрап покажет
  расхождения в логах; правки только в env.
- Один общий таймаут 40 с для всех маршрутов — длинные разборы (L3) могут
  упираться; параметризация по маршруту — по факту S-05 (async-режим).
