# Отчёт S-49 — LMS LRS-адаптер

**Дата:** 2026-11-02 · **Этап:** E-18 · **Ветка:** main (автономный режим)

## 1. Что сделано

- **Схема.** Миграция `0024_lms`: `lrs_deliveries` (statement_id unique,
  payload JSONB, status/attempts/response_status/last_error/next_attempt_at/
  sent_at).
- **xAPI builder (`domains/lms/service.py`).**
  - statements по всем ученикам: навыки (`experienced`, score scaled) и
    Elo бота (`achieved`, raw/min/max).
  - `statement_id = UUID5(actor|object|day)` — идемпотентность в рамках дня;
    повторный enqueue не создаёт дубль.
- **Доставка.**
  - `deliver_pending`: LRS `PUT /statements?statementId=...` с Basic Auth;
  - retry с экспоненциальным backoff (до 1 ч), `failed` виден в журнале;
  - без `LRS_ENABLED/ENDPOINT` — `disabled=1`, только локальный CSV.
- **Расписание.** Worker `lms_sync` (minute=15, run_at_startup) — enqueue +
  доставка; admin `POST /admin/lms/sync` для ручного запуска.
- **API/журнал.**
  - `GET /admin/lms/status` — configured/endpoint/counts/lastDelivery;
  - `GET /admin/lms/deliveries?status&limit`;
  - `GET /admin/lms/deliveries.csv` — журнал доставки;
  - `POST /admin/lms/sync` — queued/sent/failed/pending/disabled.
- **Mapping.** Activity id `https://chessclass.local/skills/{slug}` и
  `.../bots/{userId}`; LMS-курсы подключаются внешним адаптером.
- **Тесты.** Идемпотентный enqueue, успешная доставка, повтор без отправки,
  500 → failed/attempts → retry, status/CSV/sync.

## 3. Что не сделано / блокеры

- **Реальный LRS** не подключён: нет endpoint/key; проверено на fake sender.
- **LMS-курсы/классы** не маппятся автоматически: activity id стабильны,
  сопоставление курсов — на стороне LMS/адаптера.
- **UI журнала LRS** не делался: admin API/Swagger; CSV доступен.
- **OAuth2/xAPI-специфичные заголовки** не используются: Basic Auth
  (типовой LRS), при необходимости — адаптер.
- **Scheduled export** запускается каждые 15 минут, а не отдельным
  ежедневным окном; настраивается cron.

## 4. Отклонения от Design

- `statement_id` детерминирован по дню, а не случайный UUID: это даёт
  идемпотентность без отдельного dedup-поля.
- Retry-очередь в БД, а не в Redis: журнал доставки и восстановление
  переживают рестарт.
- `LRS_ENABLED` — явный флаг; без него даже endpoint не используется.

## 6. Риски

- UUID5 за день означает, что изменение навыка в течение дня не создаст
  новую запись; для ежедневного снапшота это ожидаемо.
- Basic Auth-секреты в env; не логируются.
- Backoff до часа; при длительном сбое очередь растёт — нужен alert/retention.
- LRS может вернуть 2xx без фактического сохранения; контракт LRS.
