# Отчёт S-62 — Hash-lock и воспроизводимая сборка

**Дата:** 2026-11-03 · **Этап:** E-22 Edge, supply chain и ворота CI · **Статус:** ✅

## 1. Что сделано

- **`backend/requirements.lock`** — сгенерирован через
  `pip-compile --generate-hashes` (pip-tools в контейнере базового образа
  `python:3.12-slim` — тот же слой, что для prod-сборки): **46 пакетов**,
  каждая запись со `--hash=sha256` (команда записана в шапке lock).
- **`backend/Dockerfile`** переработан:
  1. Stockfish 17.1 — `ARG STOCKFISH_SHA256=09e95322…31987d` (вычислен от
     официального `stockfish-ubuntu-x86-64-avx2.tar`, 80 087 040 байт);
     build-сценарий сверяет digest **до распаковки** — подмена/перезалив
     архива → `hash mismatch`, сборка падает;
  2. `COPY requirements.lock pyproject.toml` →
     `pip install --require-hashes -r requirements.lock` — любое
     расхождение hash любого пакета → сборка падает;
  3. сам проект — `pip install --no-deps -e .` (иначе pip снова резолвит
     зависимости из PyPI, минуя lock).
- Контрольная **сборка целиком прошла** (`docker compose build api`):
  «installed: /usr/local/bin/stockfish sha256 OK», все хэши lock сошлись
  (sqlalchemy 2.1.7 / chess 1.11.2 — sdist → wheel собирается на месте).
- **`backend/scripts/pip_audit.sh`** — `pip-audit -r requirements.lock`,
  сервис уязвимостей выбирается `PIP_AUDIT_SERVICE` (default `pypi`).
  Локальный факт: `pypi.org` JSON из этой сети блокируется (SSL EOF),
  прогон через **OSV**: `pip-audit -r … -s osv` → **No known
  vulnerabilities found**. CI (S-63) — дефолтный pypi-сервис.
- Release-truth тесты (+3): каждая запись lock с hash (блочный парсер);
  Dockerfile собирает только из lock (`--require-hashes -r`,
  `--no-deps -e .`); `STOCKFISH_SHA256=<64 hex>` + «hash mismatch» в
  Dockerfile (`tests/test_hash_lock.py`).

## 2. DoD

- [x] сборка только из lock — все runtime-зависимости образа через
  `--require-hashes -r requirements.lock`; сам пакет — `--no-deps`
- [x] hash-mismatch ломает build — сверка в build-сценарии (SF-архив — до
  распаковки; pip-пакеты — при установке); release-truth тесты держат
  контракт от откатов
- [x] контрольная сборка зелёная
- [x] hash-мismatch негатив — контрольный build с подменённым
  `STOCKFISH_SHA256=0…0` падает: `stockfish archive hash mismatch:
  09e95322…87d != 0000…` (exit 1, до распаковки и установки зависимостей)
- [x] **219 backend-тестов** (216 прошлый факт + 3 hash-lock) · ruff 0 ·
  mypy 0 (246 файлов) · doc-lint 6/6
- [x] pip-audit по lock — no known vulnerabilities (§5)

## 3. Что не сделано / блокеры

- **PEP 517 build-isolation** сам ставит setuptools из PyPI для sdist
  (chess/sqlalchemy) и `pip install -e .` — без hash-проверки. Резидуал
  → S-63 (вариант: `--no-build-isolation` + setuptools в lock, либо
  prebuilt-wheels фиксация). Риск — минимальный, известная особенность pip.
- `frontend`: `npm ci` уже работает по `package-lock.json` (lock-факт);
  `npm audit` — S-63.

## 4. Отклонения от Design (нужны ADR?)

- Нет ADR. Сборка из lock — механика реализации; потока в Design §15.1
  не меняется, факт добавлю в Design однострочником при ревизии (S-63).

## 5. Новые факты → Design (обязаны вернуться в Design?)

- `backend/requirements.lock` — новый артефакт сборки; `STOCKFISH_SHA256` —
  ARG-контракт Dockerfile (не runtime env).
- pip-audit: **No known vulnerabilities found** (OSV-база, 46 пакетов;
  pypi-JSON из данной сети недоступен — SSL EOF на pypi.org, действующая
  блокировка не дефект lock'а; CI прогонит дефолтным pypi-сервисом).

## 6. Риски

- pip-compile генерит хэши для all-платформ — дни сборки +30–50 с
  (download 46 пакетов с верифицированными wheels); приемлемо.
- Резидуал §3 — последняя щель в «только из lock» (setuptools
  build-isolation); закрывается в S-63 вместе с docker-build gate.
