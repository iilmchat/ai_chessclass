# Отчёт S-45 — Турниры ботов и экспорт в LMS

**Дата:** 2026-11-02 · **Этап:** E-16 · **Ветка:** main (автономный режим)

## 1. Что сделано

- **Схема.** Миграция `0021_tournaments`:
  - `tournaments` — name, format (`bracket|round_robin`), status
    (`draft|running|done`), created_by, meta, timestamps;
  - `tournament_participants` — seed, wins/losses/draws, points, rank;
  - `tournament_matches` — round/match, bot_a/bot_b, winner, result,
    moves/duration.
- **Турнирный движок (`domains/tournaments/service.py`).**
  - Bracket: 8 ботов → 7 матчей (4+2+1); ничья в плей-офф — детерминированно
    проходит меньший seed.
  - Round-robin: все пары; очки 3/1/0.
  - Матч: оба бота ходят в песочнице `run_bot_move`, `TOURNAMENT_MAX_PLIES=40`,
    **без LLM**; Elo/`bot_stats` не меняются.
  - Валидация: 2–16 уникальных активных ботов; чужие/неактивные → 404.
  - Аудит `tournaments.run`.
- **API/UI.**
  - `GET /tournaments`, `GET /tournaments/{id}` — лидерборд/матчи.
  - `POST /admin/tournaments` (teacher/admin) — провести турнир.
  - `GET /admin/tournaments/{id}/export.csv` — leaderboard + matches.
  - UI `/tournaments`: список, создание по ID ботов, формат, таблица
    лидеров, матчи, экспорт.
- **LMS-экспорт.**
  - `GET /admin/export/skills.csv` — student × skill: EMA, week,
    solved/streak, Elo, W/L/D, level, age_group.
  - `GET /admin/export/xapi` — statements: actor mbox, verb
    `experienced|achieved`, object skill/bot-elo, result score, timestamp.
  - Доступ teacher/admin/auditor; аудит `export.skills`/`export.xapi`.
  - UI `/export`: скачивание `skills.csv` и `xapi.json` через Bearer.
- **Тесты.** `tests/test_tournaments.py`: 8 ботов bracket → 7 матчей,
  ranks/points; CSV турнира; skills.csv/xAPI; student не создаёт турнир.

## 3. Что не сделано / блокеры

- **Античит турниров:** турнирные ходы не сохраняются в
  `bot_match_moves` и не семплируются для `engine_likeliness`; используются
  флаги обычных матчей. Для полноценного античита турниров нужна запись
  ходов (backlog).
- **Асинхронность:** турнир выполняется синхронно в запросе; для больших
  сеток/round-robin нужен arq-job + SSE (сейчас 8 ботов/7 матчей быстро).
- **Расписание** (даты/таймслоты) не делалось: турнир запускается сразу.
- **xAPI-валидация** — структурная (actor/verb/object/result), без
  официального LRS-коннектора; payload готов к адаптеру.
- **UI выбора ботов** — текстовое поле ID; полноценный picker — backlog.

## 4. Отклонения от Design

- Bracket для 8 ботов — 7 матчей, а не 28 round-robin: быстрее и
  соответствует «сетке»; round-robin доступен опцией.
- Ничья в плей-офф разрешается по seed/id (детерминированно), а не
  дополнительными партиями.
- Турнирные матчи не влияют на Elo/`bot_stats`: это отдельный режим,
  чтобы не искажать лестницу.
- Экспорт xAPI — statements, не полный LRS API; для LMS достаточно.

## 6. Риски

- Синхронный турнир блокирует воркер API на время матчей; при 16 ботах
  round-robin (120 партий) нужен async.
- Нет записи турнирных ходов → слабее античит и нет реплея.
- CSV/xAPI содержат PII (email); доступ ограничен teacher/admin/auditor,
  скачивание аудитируется.
- Ничья по seed может быть спорной; для v0.2 зафиксировано.
