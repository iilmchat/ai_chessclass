# Отчёт S-19 — Лестница-часть 2: Stockfish UCI_Elo

**Дата:** 2026-11-01 · **Этап:** E-07 Лаборатория ботов · **Статус:** ✅

## 1. Что сделано

- SF-оппоненты лестницы: `stockfish-1400` / `-1600` / `-1800`
  (SF_OPPONENTS: имя → UCI_Elo). Ход оппонента — через EngineService
  (set_strength → UCI_LimitStrength + UCI_Elo; threads=1 из config;
  movetime 300 мс профилем `analysis`); движок создаётся на матч
  и закрывается в finally (§7.3 «по инстансу на arq-процесс»).
- Семплирование ходов ученика: 10 % (`random < 0.10`) →
  `bot_match_moves.sf_sample=true` — данные для флага engine_likeliness
  (античит 2.0, E-08).
- `MatchRunIn.pattern` расширен на SF-имена.
- Тесты (+2, интеграционные против реального SF): матч random-бот vs
  SF-1400 (результат честный, ходы записаны, семплы ≥ 1), неизвестный
  SF-оппонент → отказ.

## 3. Что не сделано / блокеры

- Concurrency 2 для матчей (§7.2) — арq max_jobs глобальный; ограничение
  per-очередь — при росте нагрузки (v0.1 — один воркер, риск низкий).
- Анализ семплов (совпадение хода ученика с топ-1 SF) — античит 2.0 (E-08):
  данные уже собираются.

## 4. Отклонения от Design (нужны ADR?)

- Нет ADR. Движок SF-оппонента — на матч, а не «по инстансу на процесс
  воркера» — при одном arq-процессе эквивалентно; при росте — singleton
  в воркере (решение реализации, не дизайна).

## 5. Новые факты → Design (обязаны вернуться в Design?)

- movetime SF-оппонента — 300 мс (фиксированный короткий бюджет; Design
  задал «фиксированы» без числа) — SPEC §3.10 дополнен.

## 6. Риски

- random-бот vs SF-1400 — почти всегда loss → Elo падает к 960 (clamp) —
  ожидаемое поведение лестницы.
- SF-движок на матч: время старта ~0.1 с × матчей — приемлемо; singleton
  в воркере — оптимизация при нагрузке.
