# Отчёт S-67 — LRS OAuth2 и LMS-mapping

**Дата:** 2026-11-04 · **Этап:** E-24 Интеграции и релиз · **Статус:** ✅

## 1. Что сделано

### OAuth2 client_credentials (Bearer) + cache/refresh

- `core/config.py`: `lrs_oauth_token_url`, `lrs_oauth_client_id`,
  `lrs_oauth_client_secret`, `lrs_oauth_scope` (пустое `client_id` →
  **Basic-fallback**, прежний режим S-49). В `.env*.example` добавлены
  `LRS_OAUTH_*` переменные (env_ignore_empty=true — S-61 контракт).
- `domains/lms/service.py`:
  - `fetch_oauth_token()` — POST grant_type=client_credentials + scope;
    кэш в памяти (`_oauth_token`: value + expires_from `expires_in`).
  - `auth_headers()` — refresh при истечении (margin **60 c**) или
    отсутствии кэша; иначе Bearer из кэша.
  - `_send()` — Bearer в OAuth2-режиме, `auth=(key, secret)` в Basic;
    приоритет: наличие client_id + token_url.
  - `_http_client(base_url)` — единая фабрика httpx-клиента с egress-хуком
    (S-61) — точка инъекции MockTransport в тестах.
- `core/egress.py`: `lrs_oauth_token_url` добавлен в
  `configured_egress_patterns()` (отдельный IdP допускается).

### Маппинг классов на курсы LMS

- Миграция **`0030_s67_lms_oauth`**: `lms_courses` (external_id unique,
  title_ru) и `lms_class_map` (class_id unique, FK classes/lms_courses
  ondelete CASCADE, activity_ref). Head-count: **0030 (30)**.
- `build_statements()`: мапнутые классы дают skill-объектам
  `object.id = {activity_ref.rstrip('/')}/skills/{slug}` (был
  `https://chessclass.local/...`); дефолт — прежний корень. Statement id по-прежнему uuid5 от (actor, object, day) — **повтор sync не дублирует
  statement** (unique statement_id; финальный тест существующих
  идемпотентность-кейсов зелёный).
- API (`/admin/lms`): `GET/POST /courses`, `DELETE /courses/{id}`,
  `GET/POST /class-map`, `DELETE /class-map/{id}`, `GET /oauth-status`.
  Read — teacher+admin; write — admin; все мутации в audit; 404/409
  разделены (нет класса/курса vs дубль external_id/маппинга).
- UI: админ-панель «LMS LRS (S-67)» в `/ops` (статус/auth-mode/счётчики,
  CRUD курсов и маппингов).

## 3. Что не сделано / блокеры

- Живой LRS провайдер (Moodle-style) на staging с OAuth2 не принимался —
  тестовый LRS есть в e2e-контуре MockTransport + бэкап-стенда; приёмка с
  реальными ключами — фиксированный факт S-69 (prod-приёмка).
- Общий `lms_class_map` FK на `users.teacher` не добавлен (владелец курса
  — админ); спец-роли редакторов курсов — вне v0.4.

## 4. Отклонения от Design (ADR?)

- Нет ADR. Расширение §3.20: OAuth2 поверх Basic как опциональный режим;
  activity_ref формирует activity id — соответствует xAPI-модели
  (activity = курс LMS).

## 6. Риски

- Кэш токена in-memory: при multi-replica каждый воркер получает свой
  токен — допустимо; если IdP ограничит RPS — задать у LRS глобальный
  lease (backlog v0.5).
- Маппинг меняет object_id → statement_id. Разовый «переход» создаст
  новые statement в тот же день (двойной учёт навыка за день в LRS) —
  ожидаемо и одноразово; include-миграционных данных нет.
