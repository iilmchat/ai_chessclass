# Отчёт S-34 — Доска: drag-and-drop и мобильный UX

**Дата:** 2026-11-02 · **Этап:** E-12 · **Ветка:** main (автономный режим)

## 1. Что сделано

- **`chess.js`** добавлен как клиентский движок позиции: легальность ходов,
  FEN, история SAN, undo/redo. Серверные API не менялись.
- **ChessPage/доска.** Drag-and-drop фигур (`onPieceDrop`) и click-to-move
  (`onSquareClick`); при выборе фигуры подсвечиваются легальные поля,
  последний ход и шах королю. Ход валидируется локально; нелегальный
  drop/клик показывает ошибку и не меняет позицию.
- **Управление.** Кнопки «Отменить»/«Повторить», «Сброс», «Перевернуть»;
  история последних ходов; ввод SAN (`e4`) и UCI (`e2e4`) с Enter/кнопкой;
  FEN-поле с кнопкой «Применить FEN» и Enter, валидация FEN.
- **Мобильный UX.** `.board-controls` переносится на узких экранах, поля
  ввода занимают строку, кнопки растягиваются; доска ограничена шириной
  контейнера (существующий media-query 900px + новый 600px).
- **Тема.** Цвета светлых/тёмных полей зависят от `prefers-color-scheme`
  (хук `usePrefersDark` вынесен в `shared/usePrefersDark.ts` и переиспользован
  CodeMirror-редактором).
- **Состояния.** Ошибки хода/FEN, `busy` для инсайта, `analysisBusy`/ошибки
  PGN — отдельные, не смешиваются.

## 3. Что не сделано / блокеры

- **Выбор фигуры при превращении** — пока автоматически ферзь; отдельный
  диалог Q/R/B/N — кандидат на UX-полировку.
- **Автотест drag на touch** — S-35 Playwright; сейчас проверено браузерным
  pointer-сценарием и responsive CSS.
- Локальная партия не сохраняется в БД (это тренажёр позиции, не PGN-партия);
  PGN-анализ остаётся отдельным блоком.

## 4. Отклонения от Design

- `chess.js` добавлен на клиент для мгновенной валидации/подсветки; серверный
  python-chess остаётся источником истины для инсайта/PGN. Дублирования
  бизнес-логики нет — только UX-валидация хода.
- Цвета доски заданы inline через `prefers-color-scheme`, а не Tailwind/shadcn
  (текущий проект использует CSS-переменные; сохранили стиль).

## 5. Новые факты → Design / SPEC

- Доска — локальный `Chess`-объект; FEN синхронизируется с полем и запросом
  инсайта. API не менялся.
- `usePrefersDark` — общий хук для CodeMirror и доски.
- Для e2e: у полей есть aria-label (`FEN позиции`, `Ход в SAN или UCI`),
  кнопки — текстовые; доска — `data-square`/`data-piece`.

## 6. Риски

- Авто-ферзь при превращении может не совпасть с ожиданием пользователя.
- Локальная история не переживает reload (в отличие от черновиков кода).
- `chess.js` добавляет ~41 kB в main bundle (gzip +13.8 kB); приемлемо,
  но при желании можно лениво грузить только на /chess.
