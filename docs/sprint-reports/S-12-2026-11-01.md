# Отчёт S-12 — PGN-анализ и блюндеры

**Дата:** 2026-11-01 · **Этап:** E-04 Шахматный домен · **Статус:** ✅ (этап завершён)

## 1. Что сделано

- Миграция `0008_chess_games`: `chess_games` (pgn ≤ 2 МБ, source),
  `chess_analyses` (status pending→running→done|failed, sf/llm JSONB,
  uq по game).
- `ingestion.py` — упрощённый порт parser'а annotator (первая партия,
  mainline; InvalidPgnError/InvalidFenError; валидация позиции через
  board.is_valid).
- `classifier.py` — классификация по Δeval (config `CH_BLUNDER_CP=300`):
  best / good <50 / inaccuracy <100 / mistake <300 / blunder ≥300.
- arq `analyze_game`: пошаговые eval'ы профилем `analysis`
  (depth 10/multipv 1/150 мс — добавлен в ENGINE_PROFILES), **терминальные
  позиции не анализируются движком** (мат = ±9900, ничья 0), blunder-детект,
  сводка (plyCount/blunderCount/игроки), прогресс в Redis pubsub
  `chess:progress:{game_id}`.
- API: upload (202; `invalid_pgn`/`pgn_too_large` 422), status+сводка,
  blunders (с explanation из LLM-блока), explain (маршрут
  `chess_lab.blunder`, L2, сохраняется в analyses.llm), SSE `/events`
  (pubsub → поток; done/failed — конец).
- Приватность партий — как у сдач (чужая → 404).
- Тесты (+5): parse_pgn, invalid/oversize, pending+приватность.

## 4. Отклонения от Design (нужны ADR?)

- Нет ADR. Профиль `analysis` (short movetime × N позиций) — дополнение к
  профилям §9 (SPEC обновлён); очереди arq — единая `arq:queue` (см. S-11).

## 5. Новые факты → Design (обязаны вернуться в Design?)

- SF не анализирует терминальные позиции (после мата bestmove без info) —
  оценка из исхода (±9900/0); учтено в analyze_game_job (annotator решал
  это через анализ только позиций «до хода»).
- python-chess молча глотает невалидные токены PGN — партия обрезается;
  port'нутая проверка game.errors → InvalidPgnError (KI-012 teacher).

## 6. Риски

- Длинные партии (80+ ходов × 150 мс ≈ 12-15 с + LLM) — бюджет arq
  job_timeout 300 с выдерживает; прогресс SSE удерживает UX.
- SSE-соединения удерживают redis pubsub-подписки — при массовом
  использовании нужно закрытие по таймауту (сейчас — по done/failed или
  disconnect клиента).
