# Отчёт S-38 — Бэкапы, TLS и runbook

**Дата:** 2026-11-02 · **Этап:** E-13 · **Ветка:** main (автономный режим)

## 1. Что сделано

- **Бэкапы.**
  - `backend/scripts/backup.sh`: `pg_dump` → gzip, sha256, lock-файл,
    retention 14 дней, безопасное удаление частичного файла.
  - `scripts/backup.ps1` (Windows): custom-format dump через `docker exec`,
    `docker cp`, sha256, retention.
  - `scripts/install-backup-task.ps1`: nightly Task Scheduler (03:00).
  - `deploy/cron/chessclass-backup`: cron-пример для Linux/prod.
- **Restore.**
  - `scripts/restore-test.ps1`: проверка sha256, restore во временную
    `chessclass_restore`, проверка `users` и `alembic_version`, drop.
  - Поддерживает `.dump` (pg_restore) и `.sql.gz` (psql).
- **TLS/edge.**
  - `deploy/nginx/edge.conf`: HTTP 80 → HTTPS 443, TLS 1.2/1.3, HSTS,
    `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`,
    `Permissions-Policy`, API/SSE proxy.
  - `scripts/gen-self-signed-cert.ps1`; `deploy/certs/README.md` +
    `.gitignore` (ключи не в git).
  - prod compose: `edge`, `certbot` volume, `ENV_FILE`/`CERTS_DIR`/
    `EDGE_HTTP_PORT`/`EDGE_HTTPS_PORT`.
  - `scripts/smoke-prod.ps1`: проверка HTTPS edge + HSTS/security headers.
- **Runbook.** `docs/runbooks/operations.md`: бэкапы/restore, полный
  prod-restore, TLS/Let's Encrypt, ротация секретов, инциденты, плановые
  проверки.

## 3. Что не сделано / блокеры

- **Автоматическая регистрация cron/Task Scheduler на целевом сервере** —
  требует admin/доступа к хосту; предоставлены installer и cron-пример.
- **Offsite-копирование** бэкапов (S3/внешний диск) — инфраструктурная
  задача, вне репозитория; отмечено в runbook.
- **Let's Encrypt** проверен по конфигурации/runbook, но не выпускался:
  нет реального домена/DNS в этой среде; self-signed HTTPS проверен.
- **Certbot-сервис** не добавлен в compose; продление — cron/host по
  runbook (осознанно, чтобы не тащить ACME-состояние в репозиторий).

## 4. Отклонения от Design

- Edge nginx добавлен отдельным сервисом, web остаётся внутренним/loopback;
  TLS-терминация на edge. Это соответствует S-38 и не меняет API.
- Для локальной проверки используется self-signed; production — LE/корп.
  сертификат через `deploy/certs`.

## 5. Новые факты → Design / SPEC

- Prod edge: 80→443, HSTS, security headers, `/api/` и SSE через edge.
- `ENV_FILE` позволяет отдельный prod env без перезаписи `.env`.
- `backup.sh`/`backup.ps1` — канонические бэкапы; `restore-test.ps1` —
  безопасная проверка restore.
- `docs/runbooks/operations.md` — эксплуатационный runbook.

## 6. Риски

- HSTS `includeSubDomains` требует корректного домена/поддоменов; для
  локального стенда — self-signed.
- Бэкапы на том же диске не защищают от отказа диска; offsite — обязателен
  для prod.
- `pg_dump` под нагрузкой может влиять на БД; запуск ночью, lock уже есть.
- Сертификаты в `deploy/certs` не коммитятся; при деплое не забыть
  смонтировать актуальные.
