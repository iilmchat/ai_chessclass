## 4. Отклонения от Design (нужен ADR?)

- **Добавлен `PROXY_TRUSTED_HOSTS`.** Иначе `ProxyHeadersMiddleware` либо
  доверяет всем (`*`), либо не видит edge в Docker-сети. Доверяем только
  loopback + `172.16.0.0/12` (prod/staging), что строже `*`; это уточнение
  ADR-021/§13.4, отдельный ADR не нужен.
- **Prod/staging env переведены на `JWT_ALGORITHM=RS256`, а не только
  `JWT_LEGACY_HS256=false`.** Иначе legacy-флаг ничего не менял бы при
  HS256-основном режиме. Ключи не в git; примеры содержат пути
  `/srv/jwt/*.pem` и требуют `gen-jwt-keys.ps1`.
- **Auth burst=9, а не burst=0.** При `rate=10r/m` nginx с `burst=0` режет
  уже второй запрос; burst 9 даёт ровно 10 быстрых запросов и 11-й 429, как
  в требовании. Общий API — burst 30 (сглаживание легитимных всплесков).
- **Edge smoke использует отдельный nginx-контейнер с теми же зонами.**
  Поднимать полный prod-edge в CI дорого и требует TLS/upstream; статическая
  проверка `edge.conf` + семантический smoke покрывают директивы. ADR не
  нужен.

## 6. Риски

- **Подделка XFF при неверном доверии.** Если API доступен напрямую или
  `PROXY_TRUSTED_HOSTS=*`, клиент может подставить `X-Forwarded-For` и обойти
  per-IP лимиты. Смягчение: API только loopback/внутренняя сеть, доверие
  только CIDR edge; в примерах — `172.16.0.0/12,127.0.0.1`, не `*`.
- **Per-account lockout — DoS на аккаунт.** Атакующий может заблокировать
  вход конкретному пользователю на 10 минут. Это сознательный trade-off
  против блокировки всей школы; IP soft-limit 50/мин и edge 10/мин
  ограничивают масштаб. При инциденте — точечный `DEL` ключа (§11).
- **Rate-limit за NAT.** Все ученики школы могут выглядеть одним IP; 10/60
  req/min на IP способны дать 429 легитимному классу. Смягчение: burst,
  мониторинг `limiting requests`, повышение лимита через репозиторий; в
  перспективе — лимит по пользователю/сессии на API.
- **RS256 без ключей.** Prod/staging примеры теперь требуют
  `gen-jwt-keys.ps1`; если ключи не созданы, логин не сможет подписать токен
  (startup-warning, но не отказ старта). Проверять `/api/v1/auth/jwks`.
- **Legacy HS256.** При временном `true` старые HS256-токены принимаются;
  это расширяет поверхность атаки. В prod/staging оставлять `false`,
  warning считать инцидентом миграции.
- **`X-Real-IP` не используется middleware.** Если перед API окажется прокси,
  который передаёт только `X-Real-IP` без XFF, реальный IP не обновится;
  текущие edge/web передают оба, но при замене прокси — проверить.
- **Nginx `limit_req` считает по `$binary_remote_addr`.** За CDN/WAF IP будет
  IP CDN; нужна настройка `real_ip`/доверенных заголовков на уровне edge,
  иначе лимит затронет всех клиентов CDN.
