# Отчёт S-35 — Playwright UI-e2e

**Дата:** 2026-11-02 · **Этап:** E-12 · **Ветка:** main (автономный режим)

## 1. Что сделано

- **Playwright.** `@playwright/test` 1.64 + Chromium; `playwright.config.ts`:
  Vite на 3201, `workers=1`, `retries=1`, trace/video
  `retain-on-failure`, HTML-отчёт, webServer поднимает frontend.
- **7 сценариев** (`e2e/full-journey.spec.ts`, serial):
  1. регистрация student через API (201; вход до verify → 403);
  2. email verification (токен из dev-БД) + вход через UI;
  3. задание «Приветствие» в CodeMirror → вердикт `passed`;
  4. инсайт позиции: Stockfish-факты + объяснение;
  5. бот-матч: создание версии → SSE «Матч завершён»;
  6. дашборд: «Инфраструктура», сводка, logout;
  7. PDF родителям: admin API → файл `%PDF`.
- **Данные для e2e.** `e2e/db.ts` читает verify-токен из `email_tokens`
  (dev-email не отправляется SMTP); `E2E_DATABASE_URL` по умолчанию —
  dev pg 5438, в CI — service pg. Регистрация/verify/PDF выполняются через
  API, потому что отдельных UI-экранов для них пока нет; остальные шаги —
  через браузер.
- **CI job `e2e`.** pg/redis services, миграции+seeds, API на 8021 и arq
  worker, Stockfish + DejaVuSans, Playwright chromium; при падении
  загружаются `test-results/`, `playwright-report/`, логи API/worker.

## 3. Что не сделано / блокеры

- **Отдельная e2e-БД** — S-36: сейчас CI использует pg/redis services,
  локально — dev-БД. Изоляции и очистки между прогонами пока нет.
- **UI регистрации/verify/PDF** — отсутствуют; S-35 проверяет их через API.
  Добавление экранов — отдельная UX-задача.
- **CI-прогон** ещё не выполнен (job появится после push); при нестабильности
  S-36 зафиксирует отдельный стенд и очистку.

## 4. Отклонения от Design

- S-35 использует API+БД для registration/verify/PDF, а UI — для задания,
  инсайта, бот-матча и дашборда. Это компромисс из-за отсутствия
  соответствующих экранов; отмечено в TODO.
- Для CI используется host-запуск API/worker (не compose), чтобы не
  дублировать S-36; в CI установлены Stockfish и DejaVuSans.

## 5. Новые факты → Design / SPEC

- Playwright: `E2E_API_ORIGIN`, `API_PROXY`, `E2E_DATABASE_URL`,
  `E2E_BASE_URL`; trace/video — retain-on-failure.
- Verify-токен доступен в `email_tokens` (raw, dev); e2e читает его из БД.
- Инсайт в CI работает без LLM-ключа (echo) при установленном Stockfish.
- PDF требует DejaVuSans и writable `REPORTS_DIR`.

## 6. Риски

- Live LLM в локальном инсайте даёт ~21 с; CI с echo быстрее. При
  ужесточении таймаутов — увеличить timeout теста.
- Бот-матч требует запущенного arq worker; в CI он стартует, локально — dev
  worker. Без worker тест упадёт по таймауту.
- Dev-БД засоряется e2e-пользователями; S-36 должен дать одноразовую БД.

на отдельный стенд.
