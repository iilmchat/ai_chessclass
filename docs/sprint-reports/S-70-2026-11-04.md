## 1. Что сделано

- **`backend/llm/circuit_breaker.py`** — Redis circuit breaker:
  - состояния `closed` / `open` / `half_open`;
  - ключи `cb:state:{provider_key}`, `cb:failures:{provider_key}`,
    `cb:probe:{provider_key}`; служебный `cb:opened_at:{provider_key}` хранит
    метку открытия, поэтому `cb:state:*` остаётся ровно `"open"`;
  - порог 5 ошибок, окно 60 с, recovery 60 с;
  - HALF_OPEN допускает один probe через `SET NX` (защита от thundering herd);
  - успех закрывает breaker и удаляет счётчик, ошибка probe снова открывает;
  - значения Redis читаются и как `bytes`, и как `str` (api/worker).
- **`backend/llm/client.py`** — retry с экспоненциальным backoff и jitter:
  `delay = LLM_RETRY_DELAY_S * 2 ** (attempt - 1) + random.uniform(0, 0.5)`.
- **`backend/llm/gateway.py`** — `CircuitBreaker(redis)` в `llm_generate`:
  - у шагов цепочки появились ключи `"cloud"`, `"local"`, `"echo"`;
  - перед вызовом — `await cb.is_allowed(provider_key)`, при `False` шаг
    пропускается;
  - успех → `record_success`, ошибка → `record_failure`;
  - `fallback_from` разделён: `failover:cloud` / `failover:local` (ошибка
    провайдера), `failover:cb_open` (breaker открыт), `failover:no_config`
    (провайдер/ключ не настроен), `quota_exhausted` и
    `quota_downgrade:{tier}` (квота, как раньше).
- **Тесты:**
  - `backend/tests/test_circuit_breaker.py` — 4 unit-теста state-machine:
    открытие по порогу, блокировка, единственный HALF_OPEN-probe, успех и
    повторная ошибка probe;
  - `backend/tests/test_llm_gateway.py` — 2 интеграционных теста: 5 падений
    cloud → `cb:state:cloud="open"` и 6-й вызов в echo; HALF_OPEN-успех
    удаляет `cb:failures:cloud`;
  - `backend/tests/test_llm_client.py` — тест паузы retry с jitter;
  - `backend/tests/test_llm_economy.py` — ожидания `fallback_from` обновлены
    на `failover:cloud`;
  - `backend/tests/conftest.py` — autouse-очистка ключей `cb:*`.

## 4. Отклонения от Design (нужен ADR?)

Архитектурных отклонений нет, новый ADR не требуется.

- CB сделан **per provider** (`cloud`/`local`/`echo`), а не per route, как в
  черновике `TODO_V0.5.md`: постановка S-70 и контракт ключей
  `cb:state:{provider_key}` задают провайдера. Design §8.4 обновлён.
- Добавлен служебный ключ `cb:opened_at:{provider_key}` — чтобы хранить время
  открытия, не меняя требуемое значение `cb:state:*` (`"open"`).
- Для ошибок провайдера выбран формат `failover:{provider_key}`; это
  implementation-деталь словаря `fallback_from`, зафиксирована в SPEC §6.4 и
  runbook §5.

## 5. Новые факты → Design (обязаны вернуться в Design?)

- CB — общий для api и worker, состояние в Redis; порог 5 ошибок за 60 с,
  recovery 60 с, ровно один HALF_OPEN-probe через `SET NX`.
- Словарь `fallback_from`: `failover:*` — отказ/отключение провайдера,
  `quota_*` — graceful fallback по квоте.
- `LLM_RETRY_DELAY_S` — база экспоненты, а не фиксированная пауза.
- Факты внесены в Design §8.4, SPEC §6.4 и runbook §5; отдельный ADR не нужен.
- Token-aware rate limits из черновика `TODO_V0.5.md` не входили в постановку
  S-70 и остаются кандидатом в следующий спринт/бэклог.

## 6. Риски

- **Ложное открытие breaker.** 5 ошибок за 60 с могут быть кратковременным
  сетевым сбоем. Смягчение: local/echo fallback, recovery 60 с, один probe.
- **Глобальность per provider.** Проблемный маршрут может открыть breaker для
  всех пользователей провайдера. Это осознанный компромисс S-70; per-route
  breaker — кандидат на будущее.
- **Окно ошибок не скользящее.** Счётчик стартует с первой ошибкой и живёт
  60 с; редкие одиночные ошибки могут не открыть breaker. Для защиты от
  «долбёжки» упавшего провайдера этого достаточно.
- **Зависимость от Redis.** При недоступности Redis `llm_generate` уже не
  проходит квоту, поэтому новый отказ не добавляет отдельной точки отказа;
  поведение CB при сбое Redis стоит покрыть алертом (существующий health).
- **Контракт `fallback_from` изменился.** Внешние запросы/дашборды, искавшие
  старые значения (`cloud_not_configured`, слаг), нужно перевести на
  `failover:*`; документы обновлены.
- **Жёсткие константы.** Порог/recovery/window заданы константами, без env;
  при необходимости тюнинга — вынести в `core/config.py` отдельным изменением.
