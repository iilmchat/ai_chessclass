# Отчёт S-33 — SSE в UI

**Дата:** 2026-11-02 · **Этап:** E-12 · **Ветка:** main (автономный режим)

## 1. Что сделано

- **`shared/useEventStream.ts`.** SSE через `fetch` (Bearer access-JWT;
  `EventSource` не умеет Authorization): парсер `event/data/id`, reconnect
  с экспоненциальной задержкой (до 10 с), `Last-Event-ID`, отмена через
  `AbortController` при unmount/смене URL.
- **ChessPage: PGN-анализ.** Добавлены загрузка PGN, live-статус и прогресс
  `{ply,total}`, список блюндеров, кнопка LLM-объяснения, polling fallback
  каждые 3 с. SSE-события: `status` (`pending/running/done/failed`) и
  `progress`.
- **BotsPage: матч.** `POST /bots/{id}/match/run` теперь создаёт строку
  матча до enqueue и возвращает реальный `matchId`; UI сразу подписывается
  на `/bots/{id}/matches/{mid}/events`, показывает `running`/`ply` и
  `done/result/eloDelta`, затем обновляет матчи/статистику/лидерборд.
  Polling fallback — 2.5 с.
- **Backend SSE.** `match_events` отдаёт начальный `running` или сразу
  `done` позднему подписчику; воркер публикует progress каждые 5 полуходов.
  `chess/games/{id}/events` закрывает поток, если анализ уже done/failed.
- **Починен лидерборд.** `/bots/leaderboard` объявлен до `/{bot_id}` —
  раньше перехватывался как int и давал 422.
- **Worker FK.** В `bot_lab.match.run_match` импортируется
  `domains.auth.models` — иначе `bot_stats.user_id` FK не резолвился в
  отдельном worker-процессе (латентный баг, найден при живом матче).
- **Тесты.** Vitest + jsdom + Testing Library; 5 тестов: парсер SSE,
  fetch-поток, reconnect после сетевой ошибки. `npm test` — 5 passed.
- **CI.** В `.github/workflows/ci.yml` добавлен job `frontend` (Node 22):
  `npm ci` → `npm test` → `npm run build`; workflow переименован в `ci`.

## 3. Что не сделано / блокеры

- **Frontend e2e** — S-35 (Playwright); сейчас проверка браузером вручную.
- **Last-Event-ID на сервере** — заголовок отправляется, но backend пока
  не присваивает `id:` событиям; reconnect перечитывает текущий статус,
  чего достаточно для PGN/матчей.
- **Bot worker exception** не публикует `failed`; при падении матча UI
  останется в `running`, polling не увидит finished. Кандидат на S-36
  (наблюдаемость/надёжность).
- **SSE через prod nginx** — конфиг с `proxy_buffering off` уже есть в
  `frontend/nginx.conf` (S-30); отдельная проверка на целевом хосте — S-38.

## 4. Отклонения от Design

- Для SSE выбран `fetch`-парсер вместо `EventSource`: нужен Bearer-токен.
  Это соответствует чеклисту S-33 («fetch/EventSource, токен»).
- `match/run` теперь создаёт `bot_matches` до постановки в arq: иначе UI
  не мог получить `matchId` для SSE. Контракт обновлён в SPEC §3.10.
- Лидерборд и импорт auth-моделей — небольшие backend-фиксы, обнаруженные
  при живой проверке; архитектура не менялась.

## 5. Новые факты → Design / SPEC

- SSE-контракты: chess `status/progress`, bots `running/done`; late
  subscriber получает финальный статус; SPEC §5 переписан.
- `POST /bots/{id}/match/run` → `{matchId, status:"queued"}`.
- Фронтенд использует `useEventStream` для PGN и матчей, polling — fallback.
- Worker-процессу нужны auth-модели для FK `users` (как и standalone-скриптам).

## 6. Риски

- Долгие SSE-соединения через прокси: nginx настроен на отключение
  буферизации, но нужен smoke на prod (S-38).
- Polling 2.5–3 с создаёт фоновые запросы; при большом числе учеников
  нужен backoff/лимит (S-37 concurrency).
- При падении worker-матча нет `failed`-события — см. §3.
