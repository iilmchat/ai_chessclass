# Отчёт S-03 — Профиль, уровни, RBAC + seeds

**Дата:** 2026-10-31 · **Этап:** E-01 Фундамент (завершается) · **Статус:** ✅

## 1. Что сделано

- Миграция `0003_profile_skills`: `user_profiles` (1:1 с users: display_name,
  level, billing_tier, prefs JSONB, CHECK-энумы), `skills` (slug uq, title_ru,
  domain, domain_ref JSONB), `skill_links` (uq-пара, weight numeric(4,3)).
  **Backfill**: профиль каждому легаси-юзеру.
- `core/levels.py`: единый `Level` (novice/intermediate/advanced) + маппинги
  python/chess (ADR-002) + `resolve_level` (override на запрос, 422 при
  невалидном override — контракт SPEC).
- Домен `domains/profile/`: models / schemas / service (ensure, update,
  list_students, set_level) / router (5 эндпоинтов с RBAC и пагинацией).
- Домен `domains/cognitive/`: модели Skill/SkillLink (реестр; события/EMA — E-08+).
- JWT-клейм `level`: register создаёт профиль (novice/free), login/refresh
  кладут актуальный уровень в access-токен.
- `/readyz`: DB ok + ревизия alembic vs head (`migrationsUpToDate`), Redis,
  версия приложения.
- Seeds `db/seeds.py` (+compose-сервис `seed`): админ `admin@chessclass.dev`,
  ученики student1/student2 (`@chessclass.dev`), 11 навыков, 5 skill_links;
  идемпотентно (повторный прогон: 0/0/0).
- CI: `.github/workflows/ci.yml` (ruff → mypy → alembic → seeds → pytest на
  pg+redis services) + `scripts/ci.ps1` (локальный полный контур в контейнере).
- Документация: README.md (по образцу ai-teacher_python), docs/CHANGELOG.md,
  LICENSE (MIT), обновлены docs/SPEC.md (§2, §3.2, §7) и docs/README.md.

## 4. Отклонения от Design (нужны ADR?)

- Нет ADR. Решения уровня контракта зафиксированы в SPEC §3.2:
  - `level` меняется отдельным эндпоинтом `PATCH /profile/{id}/level` (admin);
    `PATCH /profile/me` level не принимает (конкретный эндпоинт Design §12.2
    не задан — «уровень меняет admin»).
  - `Query(alias="pageSize")` — camelCase в query-параметрах (контракт §1).
  - `level`/`billingTier` в ProfileOut допускают null только у легаси-юзеров.
