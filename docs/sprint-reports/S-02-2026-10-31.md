# Отчёт S-02 — Аутентификация

**Дата:** 2026-10-31 · **Этап:** E-01 Фундамент · **Статус:** ✅

## 1. Что сделано

- Миграция `0002_auth_domain`: `users`, `email_tokens`, `refresh_sessions`
  (BIGINT IDENTITY, FK CASCADE, CHECK-энум-значения, уникальные
  email/token/token_hash) — применена на dev-БД.
- `core/security.py`: Argon2id (параметры из config), HS256 access-JWT
  (sub/role/level/type/exp/iat/jti), `parse_duration`; `core/ratelimit.py`:
  fixed-window + auth-lockout (Redis).
- Домен `domains/auth/`: models (StrEnum-роли), schemas (camelCase DTO),
  service (верификация 24 ч, ротация refresh, reuse → отзыв всех сессий,
  password-reset), deps (`get_current_user`, `require_role` — порт teacher),
  router (8 эндпоинтов, HttpOnly-cookie `cc_refresh` path=`/api/v1/auth`).
- `db/base.py` + `db/registry.py` — Base с naming convention, реестр моделей
  для alembic (`target_metadata` подключён в env.py).
- Тесты: `tests/test_security.py` (5 юнит) + `tests/test_auth_flow.py`
  (4 e2e in-process: полный цикл, дубликат email, lockout, password-reset);
  `conftest.py` — lifespan-клиенты, очистка, `engine.dispose()` между тестами.
- Инфра: образ пересобран (+email-validator, −psycopg2-binary); `.gitattributes`
  (LF); dev-JWT-секрет ≥32 байт (PyJWT warning); убран deprecated
  `ORJSONResponse` (FastAPI 0.162 сериализует сам).

## 3. Что не сделано / блокеры

- Host-venv `.venv` создан (py3.12), но pip с хоста стабильно таймаутит на
  PyPI → тесты запускаются в контейнере (`run --rm api` + `pip install -e '.[dev]'`,
  ~40 c на прогон). Кандидат на улучшение: dev-target в Dockerfile (S-03).
- SMTP-бэкенд прод — не нужен в v0.1 (консольный по Design §13.1).

## 4. Отклонения от Design (нужны ADR?)

- Нет. Каталог §11.2 расширен `created_at` у token-таблиц (аудит) —
  зафиксировано в SPEC §3.1; каталог — минимальный набор, не запрет.
- Login требует верифицированный email (403 `auth_email_not_verified`) —
  порядок DoD «зарегистрироваться → подтвердить → залогиниться» закреплён
  контрактом в SPEC.

## 5. Новые факты → Design (обязаны вернуться в Design?)

- Повторное использование отозванного refresh → отзыв всех сессий
  пользователя (усиление §13.1) — деталь реализации, отражена в SPEC §3.1;
  правка Design не требуется.
- Найден и закрыт паттерн: side-effect-коммит ДО `raise AppError` (иначе
  `get_session` откатывает его вместе с ошибкой) — комментарий в
  `service.rotate_refresh_session`.

## 6. Риски

- Cookie `Secure` только в prod (`app_env=prod`) — за nginx/TLS в E-10.
- `X-Forwarded-For` не читаем: за реверс-прокси IP клиента будет адрес прокси
  — учесть в E-10 (доверенные прокси).
- Rate-limit ключи `rl:*`/`auth:*` не имеют TTL-дисциплины сверх окна —
  при росте домен-префиксы по Redis не размажутся (фикс. окно).
