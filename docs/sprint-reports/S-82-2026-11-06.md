## 1. Что сделано

### 1.1. Prod-профиль observability (`docker-compose.prod.yml`)

Добавлен профиль **`observability`** (не стартует по умолчанию — проверяется
и в self-test, и тестом), 5 сервисов с `container_name: chessclass-prod-*`,
сетью `ccnet` и `restart: unless-stopped`:

| Сервис | Доступ | Ключевые свойства |
|---|---|---|
| `tempo` | только внутри сети | volume `chessclass_prod_tempo:/var/tempo`, `block_retention: 168h` (7 дней), mTLS на OTLP |
| `otel-collector` | внутри сети `otel-collector:4318/4317` | OTLP in → Tempo по mTLS, метрики :8889, health-расширение :13133 |
| `prometheus` | `127.0.0.1:${PROMETHEUS_PORT:-9092}` | retention 15d, volume, `alerts.yml` → `alertmanager:9093` |
| `alertmanager` | `127.0.0.1:${ALERTMANAGER_PORT:-9093}` | Telegram, grouping, inhibit, volume |
| `grafana` | `https://<host>/grafana/` + `127.0.0.1:${GRAFANA_PORT:-3002}` | обязательный пароль, anonymous off, `serve_from_sub_path` |

Volumes: `chessclass_prod_tempo`, `chessclass_prod_prometheus`,
`chessclass_prod_alertmanager`, `chessclass_prod_grafana`. В
`x-backend-env` добавлены `OTEL_ENABLED`, `OTEL_SERVICE_NAME`,
`OTEL_EXPORTER_OTLP_ENDPOINT` — api/worker получают их автоматически.

### 1.2. Prod-конфиги (`deploy/observability/prod/`)

- `tempo.yml` — mTLS на OTLP-приёмниках (`cert_file`/`key_file`/`client_ca_file`),
  retention 168h, `usage_report.reporting_enabled: false` (egress allowlist S-61).
  HTTP API `:3200` — plaintext **внутри** сети, порт не публикуется: по нему
  читает Grafana без клиентского сертификата.
- `otel-collector.yml` — OTLP receivers, `otlp/tempo` с `insecure: false`,
  `ca_file`/`cert_file`/`key_file` (mTLS), `prometheus` exporter :8889,
  `health_check` :13133.
- `prometheus.yml.tmpl` — `rule_files: /etc/prometheus-rules/alerts.yml`,
  `alerting → alertmanager:9093`, scrape `api:8020` (Bearer `METRICS_TOKEN`),
  `otel-collector:8889`, self, alertmanager.
- `alertmanager.yml.tmpl` — Telegram (`telegram_configs`), route:
  `critical → telegram-critical` (repeat 1 h), `warning → telegram` (6 h),
  `group_by [alertname, severity, component]`, `group_wait 30s`;
  `inhibit_rules`: critical гасит warning того же `alertname/component`,
  `ChessClassApiDown` гасит остальные api-алерты; `send_resolved: true`;
  шаблон сообщения — `telegram.tmpl`.
- `alertmanager-entrypoint.sh`, `prometheus-entrypoint.sh` — рендер
  `*.tmpl` из env в `/tmp` (chmod 600, `amtool/promtool check-config` перед
  стартом): Alertmanager 0.28 и Prometheus v3 **не поддерживают**
  env-expansion конфига (проверено по `--help`). Токены не логируются.

### 1.3. TLS/mTLS и правила

- `scripts/gen-internal-certs.ps1` — внутренний CA (RSA 4096) + серверный
  сертификат Tempo и клиентский сертификат Collector (SAN
  `DNS:tempo,DNS:otel-collector,DNS:localhost,IP:127.0.0.1`, EKU
  `serverAuth,clientAuth`), права `0640`/uid `10001` (tempo/collector — non-root).
  `deploy/internal-certs/.gitignore` — ключи не в git.
- `deploy/observability/alerts.yml` — 5 правил с метками
  `severity`/`component`: `ChessClassApiDown` (`up == 0`),
  `ChessClassHighErrorRate` (5xx > 5 %), `ChessClassP95LatencyHigh`
  (p95 > 2 s), `ChessClassDLQGrowth` (`chessclass_failed_jobs > 10`),
  `ChessClassDLQGrowthRate` (`delta(...[15m]) > 5`).

### 1.4. Доступ и edge

- `deploy/nginx/edge.conf` — `location /grafana/` → `http://grafana:3000` с
  `X-Forwarded-Prefix`, WebSocket-upgrade и TLS; CSP по-прежнему излучает
  web-nginx (без дубликата на edge — тест S-61 остаётся зелёным).
- Grafana: `GF_SECURITY_ADMIN_PASSWORD` обязателен (`:?`), `GF_AUTH_ANONYMOUS_ENABLED=false`,
  `GF_USERS_ALLOW_SIGN_UP=false` — дефолтный `admin/admin` невозможен.
- `.env.prod.example` — новые ключи: `PROMETHEUS_PORT`, `ALERTMANAGER_PORT`,
  `GRAFANA_PORT`, `GRAFANA_ADMIN_USER`, `GRAFANA_ADMIN_PASSWORD`,
  `GRAFANA_ROOT_URL`, `TELEGRAM_ALERT_CHAT_ID` (+ комментарии к
  `OTEL_*`/`METRICS_TOKEN`). В `.env.example` добавлен
  `GRAFANA_ADMIN_PASSWORD` — чтобы `docker compose -f docker-compose.prod.yml
  config -q` оставался воспроизводимо зелёным (переменная обязательна).

### 1.6. Дефекты, найденные при интеграции (и исправленные)

Промежуточный smoke (параллельно с runbook-проверкой) выявил 5 проблем,
которые были закрыты до коммита:

1. `command` у Alertmanager не работает: образ имеет
   `ENTRYPOINT=/bin/alertmanager` → заменено на `entrypoint: ["/bin/sh", ...]`.
2. Tempo падал на `client_ca_file` без client-auth policy → mTLS вынесен
   только на OTLP-приёмники (HTTP API без клиентского сертификата, Grafana
   читает трейсы).
3. Collector distroless — `CMD-SHELL wget` healthcheck невыполним → healthcheck
   убран, живость контролируется target'ом в Prometheus и логами.
4. `wget https://...` healthcheck Tempo не проходил при mTLS → plaintext
   healthcheck по внутреннему HTTP API.
5. Prometheus v3 не раскрывает `${METRICS_TOKEN}` → добавлен
   `prometheus-entrypoint.sh` с рендером шаблона (как у Alertmanager).

## 3. Что не сделано / блокеры

- **Реальная доставка в Telegram-чат не подтверждена**: в репозитории нет
  боевого `TELEGRAM_BOT_TOKEN`/`TELEGRAM_ALERT_CHAT_ID` (и это правильно).
  Структурно проверено: маршрут, рендер конфига, `amtool check-config`,
  `routes test` и notify-попытка в `api.telegram.org` (лог). Финальная
  проверка «сообщение пришло в чат дежурного» — при развёртывании с реальными
  секретами по `operations.md` §10.6.
- **Alertmanager печатает URL с bot token** при ошибке доставки (поведение
  библиотеки `telebot`): лог содержит `.../bot<TOKEN>/sendMessage`. Митигация —
  ограниченный доступ к логам и retention (зафиксировано в README и отчёте §6).
- **mTLS — только на OTLP-приёмниках Tempo**; HTTP API Tempo внутри сети
  plaintext (порт не публикуется). Для мультихостового контура нужен TLS и на
  HTTP API + клиентский сертификат в Grafana — кандидат на усиление.
- **Нет автоматической ротации внутренних сертификатов** (825 дней; ручной
  перевыпуск `-Force` + restart tempo/collector описан в runbook).
- **Grafana не покрыта отдельным e2e/axe-сценарием** (проверена `/api/health`
  и datasources; UI-доступ через edge `/grafana/` — ручная проверка).
- **Retention Prometheus/Tempo не мониторится по диску**: рост данных на
  volume ограничен retention, но алерта «диск observability заполнен» нет.

## 4. Отклонения от Design (нужен ADR?)

- **ADR-021 добавлен** (prod-observability): фиксирует профиль, порты
  (loopback 9092/9093/3002), volumes, mTLS-границу, env-контракт.
- **Секреты рендерятся entrypoint'ами, а не env-expansion**: Alertmanager
  0.28 и Prometheus v3 не поддерживают подстановку env в конфиг (проверено по
  `--help`, флага `--config.expand-env` нет). Отдельный ADR не нужен —
  реализация в рамках ADR-021, ограничение задокументировано.
- **mTLS только на OTLP, HTTP API Tempo — plaintext**: без
  `client_auth_type` Tempo падал, а Grafana (datasource `http://tempo:3200`)
  не умеет клиентский сертификат из коробки. Компромисс: порт не публикуется,
  сеть изолирована; отражено в ADR-021.
- **Healthcheck collector убран** (образ distroless, нет shell/wget):
  живость — через target `otel-collector` в Prometheus и логи. Отклонение не
  архитектурное (compose-деталь), зафиксировано в Design §15.3 и README.
- **`GRAFANA_ADMIN_PASSWORD` добавлен в `.env.example`** (dev): переменная
  обязательна для prod-compose (`:?`), а `config -q` должен оставаться
  зелёным для воспроизводимости проверки RULES §6.

## 6. Риски

- **Alert fatigue**: 5 алертов, группировка по `alertname/severity/component`
  и inhibit rules снижают шум, но при массовом сбое (БД/LLM) возможен шторм:
  `ChessClassApiDown` гасит api-алерты, но worker-алерты придут отдельно.
  Кандидат на усиление — алерт «много firing сразу» и дедуп по инциденту.
- **Telegram не гарантирует доставку на 100 %**: нет ack-механизма; при
  недоступности API (egress, блокировка бота) алерты остаются в Alertmanager и
  видны в `/alerts`, но дежурный может не узнать. Резервные каналы описаны в
  `incident-response.md` §4.1; кандидат — второй receiver (PagerDuty/webhook).
- **Токен бота в логах Alertmanager** (URL в ошибке доставки `telebot`):
  логи наблюдемости считать чувствительными, ограничить доступ/retention,
  ротировать токен при утечке (`operations.md` §5).
- **TLS-конфиг**: внутренний CA живёт 825 дней, ротация ручная; при истечении
  collector перестанет слать трейсы (в логах TLS-ошибка) — добавить
  календарную проверку в §7 runbook (ежегодная проверка контуров).
- **Хрупкость вариантов конфигов**: dev-конфиги (`deploy/observability/*.yml`)
  и prod-конфиги (`prod/*`) разделены, но используют одни имена сервисов —
  расхождение возможно; митигация — тесты `test_observability_config.py`
  (12 проверок) и `observability-selftest.ps1` в релизном чек-листе.
- **`down --profile observability` снимает контейнеры всего prod-проекта**
  (compose-семантика): задокументировано в runbook, для планового гашения
  только наблюдаемости — `stop` пяти сервисов.
- **Ресурсы хоста**: Tempo/Prometheus/Grafana + Alertmanager требуют памяти и
  диска; retention 7/15 дней оценён без нагрузочного профиля (S-55/load).
