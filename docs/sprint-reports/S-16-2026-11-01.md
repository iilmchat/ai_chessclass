# Отчёт S-16 — EMA и дашборд ученика

**Дата:** 2026-11-01 · **Этап:** E-06 События навыков · **Статус:** ✅ (этап завершён)

## 1. Что сделано

- Миграция `0010_skill_scores`: `user_skill_scores` (PK user+skill, week
  ISO-строка, score Numeric(5,2) 0..100).
- `domains/cognitive/service.py`: `recalc_user_scores` (EMA α=0.3 из
  `SKILL_EMA_ALPHA`; raw = clamp(50 + Σ весов недели × 10, 0..100); без
  событий скор сохраняется), `scores_snapshot` (11 навыков + скоры, 50 =
  нейтрально), `recommendations` (skill_links: навык <40 → связанный
  тренировочный навык).
- API `/api/v1/skills`: `GET /me`, `GET /legend`, `GET /{user_id}`
  (teacher/admin), `POST /{user_id}/recalc` (teacher/admin).
- arq cron `scores_recalc` (nightly 03:40 UTC) + пересчёт активных юзеров.
- UI SkillsPage: **SVG spider-график** (11 осей, 0..100), срез-список,
  рекомендации; вход через LoginGate.
- SPEC §8 (формула EMA), §2 (эндпоинты), история.

## 3. Что не сделано / блокеры

- Тренд-стрелки (Δ между неделями) — история хранится только последней
  неделей (PK user+skill); для трендов нужна недельная история таблицы —
  v0.2 (Design §10.3 допускает).
- PDF родителям — S-19 (reports-домен, fpdf2).

## 4. Отклонения от Design (нужны ADR?)

- Нет ADR. week как строка ISO (не date) — читаемость в API; α — config
  (§10.3 «α в config» соблюдено).

## 5. Новые факты → Design (обязаны вернуться в Design?)

- Формула перевода весов в скор: raw = 50 + Σ×10 (нейтраль 50, масштаб 10)
  — Design задал только принципы; зафиксировано в SPEC §8.

## 6. Риски

- recalc в цикле по пользователям — при 1000+ юзеров nightly станет
  долгим; оптимизация (один запрос-агрегат) — при росте (v0.2).
- «Нейтральное 50» на старте может маскировать отсутствие данных — UI
  показывает week=null как «нет данных» (в срезе 50).
