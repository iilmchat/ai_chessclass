# Отчёт S-50 — Telegram-бот: уведомления ученику/учителю

**Дата:** 2026-11-03 · **Этап:** E-18 · **Ветка:** main (автономный режим)

## 1. Что сделано

- **Схема.** Миграция `0025_telegram`:
  - `telegram_links` (user_id PK, chat_id unique, consent, timestamps);
  - `telegram_outbox` (kind/text/status/attempts/last_error/next_attempt_at/
    sent_at).
- **Привязка.**
  - `POST /telegram/link` — direct chat_id + обязательный consent;
  - `POST /telegram/link-code` — код + deep link, Redis TTL
    `TELEGRAM_LINK_TTL_S` (600 с);
  - `POST /telegram/confirm` — подтверждение кода и привязка;
  - `DELETE /telegram/link` — отписка/удаление;
  - `GET /telegram/status` — linked/consent/configured/counts.
- **Уведомления.**
  - `telegram_outbox` + retry/backoff (до 1 ч), worker `telegram_deliver`
    (minute=2/startup);
  - интеграции: выдача бейджа (progress), готовый PDF (reports);
  - лимит 20 уведомлений/сутки на пользователя (Redis), отписка отключает
    очередь;
  - без `TELEGRAM_BOT_TOKEN` — graceful off (`disabled=1`), send не вызывается.
- **Безопасность.** Токен только в env, не логируется; consent обязателен;
  chat_id валидируется; rate-limit link/code 5/мин; audit
  `telegram.link/confirm/unlink`.
- **UI.** Профиль: статус, chat_id, consent, привязка/отписка, код.
- **Тесты.** link-code/confirm, outbox fake sender, consent 422, retry после
  500, отписка, graceful off без токена.

## 3. Что не сделано / блокеры

- **Реальный Telegram bot** не подключён: нет токена; webhook/`getUpdates`
  не реализованы — код/deep link подтверждается из UI/API.
- **Стрик/проверка учителем** не имеют отдельных триггеров: сервис
  `enqueue(kind=...)` готов, но события пока только бейдж/PDF.
- **Роль учителя** не получает отдельный chat: уведомления привязаны к
  пользователю; teacher-события можно добавить без смены схемы.
- **UI deep-link** показывает код, но не открывает `t.me` автоматически.
- **Ретраи** до 1 ч; при отзыве consent pending помечается failed.

## 4. Отклонения от Design

- Вместо webhook — outbox + cron: проще и переживает рестарт; webhook можно
  добавить позже.
- Код привязки хранится в Redis, не в БД; TTL 600 с.
- `TELEGRAM_BOT_TOKEN` — единственный признак включения (нет отдельного
  `TELEGRAM_ENABLED`).

## 6. Риски

- Telegram API rate limits/403 (бот заблокирован) — outbox retry, но нужен
  алерт по failed.
- chat_id уникален: повторная привязка другим пользователем даст 500 без
  отдельной обработки.
- Consent хранится как флаг; история согласий не ведётся.
- Токен в URL Telegram API; httpx не логирует URL по умолчанию, но нельзя
  включать debug-логи.
