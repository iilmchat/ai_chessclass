## 4. Отклонения от Design (нужен ADR?)

Нет архитектурных отклонений. Уточнены эксплуатационные детали: миграции
выполняет отдельный `migrate`-сервис (а не API на старте), API в prod
публикуется на loopback, web — nginx. Зафиксировано в Design §15.1/§15.3.

## 5. Новые факты → Design

- Prod-схема запуска и healthcheck-и — Design §15.1/§15.3.
- Публичный вход пока HTTP; TLS — S-38 (осознанно).
- Отчёты PDF требуют общего volume `chessclass_prod_reports` у api и worker.

## 6. Риски

- `resolver 127.0.0.11` в `nginx.conf` — Docker-DNS; вне compose upstream
  не резолвится (для edge-сценария S-38 будет отдельный конфиг).
- Один web-контейнер без edge rate-limit; до S-38 — только loopback API.
- Секреты в `.env.prod.example` — плейсхолдеры; при деплое обязательна
  ротация `POSTGRES_PASSWORD`/`JWT_SECRET`/seed-паролей.
- Cron-баг worker'а жил с S-16; регресс-тест теперь ловит импорт
  `WorkerSettings` в CI.
