# Отчёт S-21 — trivial_bot

**Дата:** 2026-11-01 · **Этап:** E-07 Лаборатория ботов · **Статус:** ✅ (этап завершён)

## 1. Что сделано

- `bot_lab/trivial.py`: эвристика тривиального бота. Ключевой признак —
  **захардкоженные UCI-ходы** в коде («ходы из кармана», confidence 0.80);
  с коротким кодом (≤ `BOT_TRIVIAL_MIN_LINES` содержательных строк) — 0.90.
  Minimal random-бот из туториала (2 содержательные строки, без
  захардкоженных ходов) — **валиден, флага нет**.
- Флаг записывается при сохранении версии бота (kind `trivial_bot`,
  domain `bot`, evidence: reasons/codeLines/hardcodedMoves/matchesPlayed);
  не блокирует ничего (§9.1, ADR-005).
- Повторяющийся паттерн против random — заготовка (требует ≥ 3 матчей;
  анализ истории ходов — E-08).
- Config: `BOT_TRIVIAL_MIN_LINES=5` (env).
- Тесты (+2): тривиальный бот → флаг с reason'ами; валидный random-бот —
  без флага.

## 2. DoD

- [x] тривиальный бот получает флаг — `return 'e2e4'` → флаг 0.90
  (hardcoded_moves + short_code)
- [x] валидный бот не трогается — random-бот без захардкоженных ходов
  флага не получает
- [x] pytest **139 passed** · ruff 0 · mypy 0 (133 файла)

## 3. Что не сделано / блокеры

- Повторяющийся паттерн (10 матчей против random с одинаковым
  ход-последовательностью) — анализ bot_match_moves истории (E-08
  античит-дашборд вместе с engine_likeliness).

## 4. Отклонения от Design (нужны ADR?)

- Нет ADR. «Длина кода < порога» из §9.2 уточнена: короткий код сам по
  себе не флаг (иначе валидный minimal-бот ложно срабатывает) — только
  усилитель вместе с ходами из кармана. Порог — config.

## 5. Новые факты → Design (обязаны вернуться в Design?)

- Карта признаков trivial_bot: hardcoded_moves (0.80) > short_code
  (усилитель 0.90) — SPEC-таблица античита дополняется в E-08 (сейчас —
  evidence в флагах).

## 6. Риски

- Обфускация hardcoded ходов (строки собираются из частей) уйдёт от
  regex-эвристики — против глубокой обфускации работает judge-сессия
  (unexplained_code, E-08).
