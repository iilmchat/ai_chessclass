# Отчёт S-36 — Отдельная e2e-БД и стенд

**Дата:** 2026-11-02 · **Этап:** E-13 · **Ветка:** main (автономный режим)

## 1. Что сделано

- **`docker-compose.e2e.yml`** — отдельный проект `chessclass_e2e`:
  - db `5439` (pgvector 17), redis `6385`, api `8021`, web `3201`;
  - volumes `chessclass_e2e_pgdata`, `chessclass_e2e_reports`;
  - setup-сервис: `alembic upgrade head && python -m db.seeds`;
  - api/worker ждут setup; web — nginx-образ frontend, proxy на `api:8020`;
  - LLM выключен (`LLM_BASE_URL=""`) → echo; Stockfish/DejaVu внутри
    backend-образа; `REPORTS_DIR=/srv/reports`.
- **`scripts/e2e.ps1`**:
  - `up` — собрать/поднять, дождаться readyz/web;
  - `test` — `down -v` → `up --build` → Playwright → `down -v` в finally;
  - `reset` — удалить e2e-volumes; `down` — остановить без удаления;
  - `logs` — логи стенда.
- **Изоляция.** Отдельные project/container names, volumes и порты; dev-стек
  продолжает работать параллельно. Никаких `.env`/volume от dev не
  используется; LLM-ключи не нужны.
- **CI.** Job `e2e` уже работает на отдельных pg/redis services и host API
  8021/worker; локальный compose-стенд — для воспроизводимого прогона на
  машине разработчика.

## 3. Что не сделано / блокеры

- **CI использует services, а не compose-стенд.** Это осознанно: текущий
  job зелёный и не требует Docker-in-Docker; S-36 даёт локальный
  воспроизводимый стенд. При желании CI можно перевести на
  `docker-compose.e2e.yml` отдельной задачей.
- Первый `up --build` занимает время на сборку backend/frontend образов;
  последующие — из кэша.

## 4. Отклонения от Design

- «Compose-profile» реализован как отдельный compose-файл с project name
  `chessclass_e2e`, а не profile внутри dev-compose: profiles не меняют
  project/volumes/порты и рисковали бы dev-БД. Это строже по изоляции.
- E2E web — production nginx-образ, а не Vite dev; так проверяется реальная
  раздача SPA/прокси.

## 5. Новые факты → Design / SPEC

- E2E-стенд: db 5439, redis 6385, api 8021, web 3201; volumes
  `chessclass_e2e_*`; setup = migrate+seed.
- `scripts/e2e.ps1 test` — канонический локальный прогон; Playwright env:
  `E2E_API_ORIGIN=http://127.0.0.1:8021`,
  `E2E_BASE_URL=http://127.0.0.1:3201`,
  `E2E_DATABASE_URL=postgresql://chess:chess_e2e@127.0.0.1:5439/chessclass`.
- LLM в e2e не нужен (echo); PDF/Stockfish — внутри backend-образа.

## 6. Риски

- Порты 5439/6385/8021/3201 должны быть свободны; при конфликте — изменить
  в compose/скрипте.
- `test` удаляет e2e-volumes; артефакты Playwright остаются в
  `frontend/test-results`/`playwright-report` (в git не попадают).
- Docker-сборка первого прогона тяжёлая (backend Stockfish + frontend npm ci).
