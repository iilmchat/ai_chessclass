# Отчёт S-43 — Генерация этюдов «код + LLM»

**Дата:** 2026-11-02 · **Этап:** E-16 · **Ветка:** main (автономный режим)

## 1. Что сделано

- **Схема.** Миграция `0019_studies`:
  - `chess_studies` — `title`, `fen`, `condition_text`, `theme`,
    `difficulty`, `solution_uci`, `solution_line jsonb`, `status`
    (`draft|review|published|rejected`), `source`, `generator_meta jsonb`,
    `created_by/reviewed_by`, `reviewed_at`, `review_note`;
  - индексы по статусу; FK `SET NULL` для авторов.
- **Генератор (`domains/studies/service.py`).**
  - `STUDY_CANDIDATES` — курируемые легальные позиции (8) с темой/сложностью;
    выбор кандидата (случайный/детерминированный в тестах).
  - SF-валидация через `chess_lab.run_engine_analysis` (SF только worker;
    API → arq): лучший ход + PV, проверка легальности.
  - LLM-маршрут `chess_lab.study` (L1, temperature 0.5, max 300) формирует
    условие; при ошибке LLM — безопасный fallback-текст.
  - `STUDY_DAILY_LIMIT=10` на пользователя/сутки (429 `study_limit`).
  - Черновик `draft`; аудит `studies.generate`.
- **Ревью и публикация.**
  - `POST /admin/studies/{id}/submit` — draft → review (автор/admin).
  - `POST /admin/studies/{id}/review` — teacher/admin: approve/reject;
    review → published/rejected; `reviewed_by/at`, note; аудит.
  - `GET /admin/studies?status` — очередь (teacher/admin; auditor read-only).
- **Публичный API.**
  - `GET /studies` — только published; `GET /studies/{id}` — published.
  - `POST /studies/{id}/attempt { moveUci }` — легальность + сверка с
    эталоном; `{correct, message, nextUci}`; аудит `studies.attempt`.
  - Solution/PV не отдаются в публичном DTO.
- **Тесты.** `tests/test_studies.py`: 5 этюдов генерируются (fake SF/LLM),
  проходят submit → approve → published, решаются учеником; reject-брань
  не попадает в ленту; неверный/нелегальный ход обрабатывается.
- **LLM.** Добавлен маршрут/шаблон/параметры `chess_lab.study`; тест реестра
  обновлён.

## 3. Что не сделано / блокеры

- **UI этюдов/ревью** не делался: API + Swagger; экран можно добавить в
  S-44/S-45 (вовлечение).
- **Случайный playout-генератор** не используется: выбран курируемый пул
  кандидатов + SF-валидация — воспроизводимо и не генерирует «пустые»
  позиции. При расширении — заменить/дополнить.
- **История попыток** не сохраняется (только аудит факта); для аналитики
  нужна таблица `study_attempts` (backlog).
- **Многоходовые этюды**: проверяется первый ход; `nextUci` возвращается
  для продолжения, но полноценный solver не реализован.
- **Реальная LLM-генерация** проверена через fake в тестах; live-качество
  условия зависит от RouterAI и требует ручного ревью (что и есть процесс).

## 4. Отклонения от Design

- «Генератор позиций» — курируемый пул + SF, а не случайный playout:
  гарантирует легальность/осмысленность для v0.2.
- SF вызывается через существующий arq-путь; в тестах — инъекция fake
  анализатора, чтобы не зависеть от worker/Stockfish.
- Публичный DTO не содержит solution; эталон виден только teacher/admin
  в admin-очереди.
- Ревью доступно teacher/admin; auditor только читает очередь.

## 6. Риски

- Курируемый пул быстро исчерпается/повторится; нужен генератор
  playout/этюдная база и дедупликация по FEN.
- LLM может раскрыть решение в условии; промпт запрещает, но нужен
  автоматический/ручной чек (ревью учителя — обязательный gate).
- Генерация зависит от SF/arq; при недоступности — 502, черновик не
  создаётся.
- Один ход ≠ полное решение многоходового этюда; для v0.2 это
  «найди лучший ход», зафиксировано.
