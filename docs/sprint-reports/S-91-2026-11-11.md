## 4. Отклонения от Design (нужен ADR?)

- **Teacher теперь видит только учеников своих классов**, а не всех учеников
  платформы (поведение v0.1 «малая школа»). Это требование S-91/BOLA; матрица
  §4.4 и тесты обновлены. Отдельный ADR не нужен — уточнение уже принятой
  модели классов S-40.
- **`require_scope` стал fail-closed:** отсутствующий `auditor_scope` теперь
  403, а не «разрешено». Это меняет поведение auditor по умолчанию; тесты
  `test_audit.py`/`test_auth_hardening.py` обновлены (scope выдаётся явно).
- **Чужой существующий объект → 403, а не 404.** Раньше боты/партии/карточки
  скрывались как 404; для BOLA-диагностики и требований спринта выбран 403.
  Отсутствующий объект по-прежнему 404.
- **Student может скачать свой PDF.** Матрица §4.4 обновлена: «свой — ✅».
  Это соответствует проверке владельца; чужой PDF по-прежнему 403.
- **Audit teacher — только `actor_id == self`.** Учитель не видит действия
  других учителей; полный журнал — admin/auditor. Логи по ученикам учителю
  через этот endpoint не раскрываются (осознанно).
- Новый ADR не требуется: S-91 — реализация уже заявленной модели ролей и
  классов.

## 6. Риски

- **Будущие эндпоинты могут забыть вызвать authz-хелпер.** Нет
  middleware-level policy; защита зависит от дисциплины роутеров и ревью.
  Смягчение: таблица §3.33, тесты на каждый `{id}`-роут, code review;
  в перспективе — policy-middleware/декоратор.
- **403 раскрывает существование объекта.** Для BOLA-диагностики это удобно,
  но даёт лёгкую энумерацию ID. Если скрытность важнее — вернуть 404 для
  чужих объектов (единым изменением хелперов).
- **Teacher зависит от членства в классе.** Если ученика забыли добавить в
  класс, учитель получит 403 на законные данные. Это операционный процесс
  (runbook §12), а не баг authz; нельзя «чинить» выдачей admin.
- **Per-account/role fallback.** Admin по-прежнему видит всё; компрометация
  admin-аккаунта обходит object-level проверки. Нужны сильные admin-пароли,
  аудит и минимальное число администраторов.
- **Списки и RLS.** Object-level фильтры дополняют RLS S-72, но не заменяют
  её; запросы без `WHERE` в новом коде всё ещё могут обойти фильтры. Ревью
  SQL и RLS-тесты обязательны.
- **Производительность.** `teacher_student_ids` — подзапрос на каждый
  список/объект; на больших классах нужен индекс `class_members.user_id`
  (есть) и мониторинг p95.
- **Auditor scope.** Явный scope теперь обязателен; при миграции старых
  профилей без `prefs.auditor_scope` аудитор получит 403 на всё — это
  fail-closed, но требует выдать scope при развёртывании.
- **403 на PvP/Anticheat** может маскировать реальные баги связей
  (ученик не в классе, комната без guest); runbook §12 даёт SQL-проверки.
