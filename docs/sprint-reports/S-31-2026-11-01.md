# Отчёт S-31 — Живой LLM-провайдер и FinOps

**Дата:** 2026-11-01 · **Этап:** E-11 · **Ветка:** main (автономный режим)

## 1. Что сделано

- **RouterAI подключён.** `LLM_BASE_URL=https://routerai.ru/api/v1` +
  `LLM_API_KEY` в корневом `.env` (в git не попадает). Dev-compose теперь
  передаёт `.env` в `api`, `worker`, `migrate`, `seed`; тесты герметичны —
  `pytest_configure` отключает живой LLM, чтобы CI не ходил в сеть.
- **Слаги и цены сверены с каталогом.** В `.env.example` и дефолтах
  зафиксированы полные id RouterAI (с префиксами): `minimax/minimax-m3.1-flash`,
  `deepseek/deepseek-v4.1-flash`, `reflection/beam-1.0-501b-a23b`,
  `anthropic/claude-sonnet-5.5`, `google/gemini-3.1-flash-lite`. Цены ₽/1M
  обновлены из `pricing` каталога (2026-11-01).
- **Judge-модель.** RouterAI Decider (`perplexity/pplx-decider-flash-v1.2`)
  использует decisions-API (`output_modalities=["decisions"]`), а не
  OpenAI chat; judge-route ожидает текст. Для S-31 judge переведён на
  chat-совместимый Gemini 3.1 Flash Lite; ADR-009 помечен superseded.
- **`GET /admin/llm/health`.** Отдаёт `status: ok|degraded|echo`,
  `providerConfigured`, `baseUrl`, доступные модели (≤50), сверку всех
  тиров (`available`/`missingModels`), последний вызов, p95 latency по
  ok-вызовам, расход за UTC-день и дневные бюджеты. Сеть ограничена 5 с.
- **`scripts/llm_smoke.py`.** 4 живых маршрута: L1 comment, L2 explain_code,
  L3 insight (advanced), judge. Пишет `llm_calls` с `user_id=NULL`
  (system-вызовы, квоты не расходуются), код 2 при echo/ошибке.
- **Устойчивость провайдера.** Пустой `message.content` (reasoning-модель
  израсходовала `max_tokens`) больше не превращается в строку `"None"`:
  retry → fallback. Ошибка записи FinOps не повторяет уже оплаченный
  LLM-вызов (раньше попадала в общий fallback-try).
- **Embeddings.** Если `LLM_EMBED_MODEL` пуст, `EmbeddingProvider` сразу
  использует hash-фолбэк, а не делает заведомо неуспешный `/embeddings`.
- **Runbook.** `docs/runbooks/llm-gateway.md`: конфигурация, health/smoke,
  ротация ключа, LM Studio, fallback/квоты, диагностика.

## 3. Что не сделано / блокеры

- **L3_alt в живом вызове.** Модель проверена health-эндпоинтом
  (`available=true`), но отдельного маршрута, который её использует,
  нет: это резерв для L3. Прямой вызов не включён в smoke, чтобы не
  платить за Claude без сценария.
- **Decider-адаптер.** Если нужен именно Decider (decisions-API), нужен
  отдельный провайдер/схема ответа; в S-31 сознательно не делали.
- **Reasoning-бюджеты.** DeepSeek V4.1 Flash тратит заметную часть
  completion-токенов на reasoning (в smoke 1830 completion). Для коротких
  маршрутов (`hint`, max_tokens 300) при явном ограничении возможен
  пустой content → fallback. Сейчас домены не передают `max_tokens`,
  поэтому на практике вызов проходит; отдельная задача — reasoning_effort.
- **TLS/прод-деплой** — S-38; живой ключ сейчас в dev-`.env`.

## 4. Отклонения от Design

- **Judge: Gemini 3.1 Flash Lite вместо Decider Flash V1.2.** Причина —
  несовместимость decisions-API с OpenAI chat-контрактом judge-route.
  ADR-009 помечен superseded; таблица §8.3 и SPEC §6.2 обновлены.
- **Цены L2** в Design были 26/100 ₽/1M (фактически это уровень Beam);
  по каталогу DeepSeek V4.1 Flash — 5.7598/22.1178. Исправлено.
- **Полные slug'и.** Дизайн использовал короткие имена; RouterAI требует
  provider-префиксы. Это не архитектурное отклонение, а факт каталога.

## 5. Новые факты → Design / SPEC

- RouterAI `/v1/models` — 584 модели; цены в `pricing` за токен, умножать
  на 1e6 для ₽/1M.
- `usage.cost` в ответе RouterAI не совпадает с расчётом по `pricing`
  (скидки/округление); FinOps считает по env-ценам, это осознанно.
- Reasoning-модели возвращают `message.reasoning` и могут отдавать
  `content=null` при исчерпании бюджета.
- Decider — decisions-API, `supported_parameters=[]`, не chat.
- Для standalone-скриптов с `llm_calls` нужно импортировать
  `domains.auth.models` (FK `users`) до создания сессии.

## 6. Риски

- Каталог RouterAI меняется (модели/цены); health покажет `degraded`,
  но цены нужно периодически сверять вручную.
- Ключ RouterAI в `.env`: при утечке — немедленная ротация (§4 runbook);
  в логи/отчёты ключ не попадает.
- Reasoning-модели увеличивают latency (14 с на L2) и completion-токены;
  при росте нагрузки нужен `reasoning_effort`/лимиты по маршрутам.
- `usage_daily` не включает system-вызовы smoke (`user_id=NULL`);
  health `today` считает по `llm_calls`, поэтому расходится с FinOps-отчётом
  по пользовательским квотам — это ожидаемо.
