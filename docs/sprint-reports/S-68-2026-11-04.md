# Отчёт S-68 — Telegram webhook, teacher-события, алерты

**Дата:** 2026-11-04 · **Этап:** E-24 Интеграции и релиз · **Статус:** ✅

## 1. Что сделано

### Webhook Telegram (public, secret-аутентификация)

- `POST /api/v1/telegram/webhook` (`domains/telegram/router.py`) — без
  CurrentUser; Telegram присылает заголовок
  `X-Telegram-Bot-Api-Secret-Token`, он сравнивается с новой
  `TELEGRAM_WEBHOOK_SECRET` (пустой секрет → 404 — webhook выключен;
  неверный → 403). Успех — всегда `{"ok": true}` независимо от
  содержимого update'а (правило Telegram).
- Обработка: `/start <link_code>` — Redis `telegram:link:<code>` →
  привязка (consent=true) + погашение кода; `/stop`/`/unsubscribe` —
  удаление привязки; прочее — help-ответ. Ответ бота — прямой
  `sendMessage` (`_reply`); ошибки логируются, не прерывают 200.

### Long-poll fallback (worker cron)

- `TELEGRAM_POLL_ENABLED` + `poll_updates_once()`: один цикл
  `getUpdates` (лимит, offset сохраняется в Redis
  `telegram:lp:offset`), Redis-лок `telegram:lp:lock` против нескольких
  воркеров; update'ы прогоняются через тот же `handle_update`.
- worker: cron-задача `telegram_poll` (каждые 2 мин; run_at_startup).

### Teacher-события (outbox)

- `enqueue_teacher_events()`: учителям всех классов ученика ставится
  outbox (kind + текст + «(ученик: email)»); без consent — пропуск.
- Хуки: `progress.record_passed_solution` → `teacher_submission`
  («Задание #N сдано (тема)»); tournaments после done →
  `teacher_tournament` («Турнир завершён»); `pvp.add_complaint` →
  `teacher_complaint` (обоим игрокам). Сбой уведомлений не роняет
  основное действие (только warning).

### Алерты интеграций (/ops)

- `observability.alerts()`: новые коды `telegram_outbox_failed`
  (count failed > 0) и `lrs_deliveries_failed` — severity warning;
  страница `/ops` показывает их уже существующим рендером списка.

  всех `.env.example` файлах.

- worker: +1 cron (`telegram_poll`).
- doc-lint B (alembic head) — не менялся (без миграций).

## 6. Риски

- Long-poll в multi-replica: лок одного воркера 90 с; при смерти
  процесса лок тает TTL — другой воркер подхватится. Webhook —
  предпочтительный путь (staging, S-69).
- teacher-события по классам: ученик в нескольких классах →
  уведомление каждому учителю (сделано сознательно); спам ограничен
  дневным лимитом S-20 на пользователя.
