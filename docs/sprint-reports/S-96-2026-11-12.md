## 3. Что не сделано / блокеры

- **Live-проверка через физическую станцию — ожидает оператора.** Туннель,
  LM Studio и токен настраиваются на Windows-ПК; в этой сессии доступа к
  нему нет. Mock-проверка подтверждает формат/метрики скрипта, но не
  реальный GPU.
- После запуска оператор должен выполнить `test-gpu-tunnel.ps1` с сервера
  и приложить вывод (models/chat/latency/tokens-per-second).

## 4. Отклонения от Design (нужен ADR?)

- **Добавлен `LLM_LOCAL_MODEL`.** Без него gateway отправлял в LM Studio
  облачный slug (`qwen/qwen3.7-flash`), которого там нет. Явная модель —
  минимальное расширение контракта, зафиксировано в Design §8.4/SPEC §6.4.
- **`network_isolation_enforced` к LLM-шлюзу не применялся.** Это поле
  sandbox (S-97), а не LLM; эквивалент отказа туннеля — `fallback_from`
  (`failover:local`/`failover:cb_open`) и breaker local. Отдельный
  bogus-флаг в LLM-метрики не добавлялся.
- **Туннель на SSH, не WireGuard.** В runbook §6 уже был SSH-черновик;
  для Windows OpenSSH + Scheduled Task проще и не требует установки
  WireGuard. ADR не нужен (транспорт, не архитектура).

## 6. Риски

- **Туннель/станция недоступны.** Windows уснул, LM Studio закрыт, SSH
  оборвался → local шаг падает, breaker local открывается, шлюз уходит в
  echo. Cloud-маршрут не страдает; алертов на local пока нет — смотреть
  `fallback_from`/`llm_calls`.
- **`LLM_LOCAL_FALLBACK=true` при недоступной станции** добавляет попытку
  local с таймаутом; после 5 ошибок breaker исключает её. Не ставить true
  без работающего туннеля.
- **Токен LM Studio в env.** Хранить только в секретах; ротация при утечке;
  не публиковать 1234 в интернет, bind туннеля — только docker gateway.
- **`GatewayPorts clientspecified`** разрешает клиенту выбирать bind;
  ограничить firewall/sshd и не давать недоверенным пользователям SSH.
- **Модель/VRAM.** 7B Q4_K_M помещается в 12 GB, но context >8192 или
  параллельные запросы могут вызвать OOM/деградацию; следить за latency/
  tokens-per-second.
- **Windows Scheduled Task** работает только после входа пользователя;
  после перезагрузки без входа туннель не поднимется (настроить auto-login
  или службу — вне scope).
